# 公众号热点原文证据钩子生成实现

## 目标

公众号热点用于增强开头的及时性、传播力和阅读张力，不作为需要单独插入正文的新闻摘要。热点加入后必须更快地把读者带到文章原本要回答的问题，不能扩大文章主题，也不能依靠 AIHOT 摘要补写人物、数字、原话或现场。

## 实现逻辑

链路由原来的一次模型调用拆成四层。

1. 候选排序。模型只根据文章、内容类型和 AIHOT 候选判断连接强度，最多返回三个候选，不写正文。
2. 原文抓取。系统按排序抓取候选的原始来源，复用知识库现有的 XCrawl、渲染代理和本地抓取能力。本地抓取逐次检查重定向目标，阻止本机、内网和保留地址。
3. 证据抽取。原文被净化、去重、分段并生成稳定证据 ID。证据模型只返回原文中的连续逐字摘录，系统确定性检查摘录是否真实存在。至少两个细节通过检查后才允许进入生文。
4. 开篇改写。生文模型只能使用已验证细节写热点事实，必须返回钩子类型、事实锚点、读者张力、过渡问题和证据引用。系统要求热点改写包含首个结构模块，最多改写两个章节，并继续执行公众号 human-writing 与正文回归检查。

本轮补充了热点改写章节的独立中文成稿门禁。即使旧稿已经存在同类风格问题，新生成章节也不能再带入提示性冒号、破折号或翻案腔。“不在……而在……”已经纳入翻案腔识别，避免旧稿问题掩盖新开头的问题。

2026-08-17 继续补充完整句法节奏门禁。公众号 human-writing 配置升级为 `human-writing.wechat.v1.2.0`，要求同一主语的连续动作、同一因果链和尚未讲完的判断沿句子主干展开。系统会识别连续四句长度接近，以及后句只用“这组数字”“这个结果”等指代短接前句的机械断句，并要求模型合并为完整的主从句或因果句。

整篇重生成会同时带入当前文章、热点计划和可追溯来源，生成的新版本保存 `previousArtifactId` 与原热点集成记录。历史批次的知识快照如果已退出当前目录，只能在产品身份、冻结输入快照和正文知识来源 ID 三方一致时继续使用，不能仅凭旧批次 ID 绕过来源检查。

前三名候选会依次尝试。原文抓取失败、正文信息量不足、逐字证据不匹配、写作结果不合规时自动尝试下一个候选。全部失败则保留原正文，不用热点摘要兜底生成。

## 底层原因

旧链路把“选热点、找角度、改标题、写摘要、重写章节”放在一次调用中。模型只有 AIHOT 标题和摘要，最安全的完成方式就是概括热点，再用模板化转场接回文章。相关度可以通过，开头仍然僵硬。

新链路把选题证据和表达分开。系统先决定材料是否存在，再决定怎样写。模型不能用写作流畅度掩盖证据不足，生成失败也不会污染当前正文版本。

## 对使用者的影响

- 点击“加入热点”会比过去耗时更长，因为需要抓取原文并执行两次事实与表达处理。
- 成功结果会新增热点来源标题、抓取方式、内容哈希和证据片段 ID，后续可以追溯开头事实来自哪里。
- 某些登录墙、纯客户端页面或过短的社交动态会被跳过。用户看到的是“没有形成可追溯开篇”，不会得到一段凭摘要扩写的内容。
- 原正文始终保留为上一版本，只有全部检查通过后才新增热点版本。
- 人工修订保存后会重新执行事实、结构、句法和排版检查，并据此刷新阻塞状态，不再出现“正文已改对但页面仍保留旧错误”的情况。

## 质量门禁

- 原文至少提取三个有效片段和 360 个正文字符。
- 逐字证据至少两条，`exactQuote` 必须是对应原文片段中的连续文本。
- 生文使用的证据 ID 必须同时属于已抓取片段和已验证细节，并进入章节 `citations`。
- 热点必须改写第一个结构模块，最多改写两个章节。
- 热点只承担开篇作用，目标占全文前 15% 以内。
- 公众号 human-writing 禁令和原有事实、结构、推广门禁继续生效。
- DeepSeek 的 API Key、模型和 Base URL 通过安全环境加载器进入 Docker 生成容器，不经 Compose env 文件解析，避免凭证中的特殊字符被插值。

## 复盘与后续

本次最重要的经验是，传播性不能靠 Prompt 要求“写得更吸引人”。稳定传播力来自可用材料、清晰的叙事职责和失败关闭机制。后续若热点抓取失败率偏高，应优先完善渲染抓取供应商和来源适配器，不应降低证据门槛或恢复摘要扩写。
