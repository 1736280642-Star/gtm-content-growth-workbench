# AI 前台账号连接与记忆隔离实现

## 结论

AI 前台测试从“设备发现平台标签页”升级为“用户点击已绑定账号连接”。平台凭证仍保留在用户本机 Chrome Profile；工作台只保存用户自定义别名、设备、平台、隔离策略和验证状态。

## 实现逻辑

```text
一次性设备配对
-> 在扩展中绑定账号别名并声明样本类型
-> 托管页读取真实产品和账号连接
-> 用户点击账号
-> 创建绑定 connectionId 的正式任务
-> 托管页即时唤醒扩展
-> 非聚焦窗口打开平台新会话
-> 隔离预检
-> 自动发送、采集、脱敏、回传并关闭窗口
```

核心数据源为 `ai_frontend_connections`。`capture_tasks.connection_id` 固定任务执行账号；租约和证据上传都校验连接与设备的一致性。

## 记忆隔离

正式结果分为两个样本池：

- `neutral_benchmark`：默认同时要求专用中立 AI 账号、没有既往 JOTO 历史、关闭平台记忆/历史引用、没有自定义指令，以及平台新会话；任一检查不通过即停止，不写入正式基线。
- `personalized_user_sample`：允许使用日常账号，只表示真实个性化体验，不与中立基线混算。

证据包写入 `isolationAttestation`，包含策略、逐项检查结果、账号历史与记忆设置的人工确认时间、适配器版本和检查时间。账号级设置由用户保留最终确认权；页面级新会话由适配器自动验证。平台没有稳定可验证的设置入口时，系统不会擅自修改用户账号设置。

## 底层原因

新会话只隔离当前对话线程，不能证明账号级记忆、历史引用或自定义指令没有参与回答。Chrome Profile 也只能隔离本地 Cookie 与登录态，不能清除平台服务端记忆；而仅使用一个初始干净账号，第一次测试后也可能被平台记住。因此可重复的中立基线必须同时关闭账号记忆，并使用没有自定义指令的独立测试账号；临时会话可在平台明确支持且适配器能验证时作为替代隔离方式。

Chrome 扩展只能在 Chrome 进程运行时执行。Windows 桌面伴侣负责 Chrome 完全关闭时启动指定 Profile，并将 Runner 作为隐藏子进程保持运行。

## 对使用者的影响

- 首次使用需要安装扩展、输入一次配对码，并为每个平台绑定账号别名。
- 日常只需在托管页点击账号，不需要提前打开 AI 页面。
- 验证码、登录失效和平台安全挑战仍需人工处理。
- 中立基线账号不能承担任何日常 JOTO 研究；已有相关历史的账号必须绑定为 `personalized_user_sample`。

## 验收

1. Chrome 正在运行但没有 AI 平台标签页时，点击连接仍能自动执行。
2. Chrome 完全关闭时，桌面伴侣能启动指定 Profile；扩展恢复后领取任务。
3. 执行窗口不抢占当前工作窗口，成功后自动关闭。
4. 任务只能由 `connectionId` 对应设备领取。
5. 中立基线缺少隔离证明时，服务端拒绝证据入库。
6. 工作台、Runner、扩展和证据均不包含 Cookie、密码、Token、浏览器存储或私有请求头。
7. 登录或隔离失败会写回任务与账号状态，不会长期停留在“执行中”。
