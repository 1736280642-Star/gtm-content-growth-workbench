# 3027 自动发布前台接入说明

## 1. 结论

3027 前台已经接入统一机器发布链路：

```text
已确认终稿
-> Publish Job
-> 常驻 Worker
-> reconciliation
-> 公开 URL 自动回填
-> 24h / 72h 存活验证
-> reliability 准入判断
```

前台不直接操作平台页面，也不等待浏览器长任务。它只负责创建耐久任务、展示状态、触发只读核验排队和呈现异常；实际发布和核验由项目已有 `direct-publish-worker`、bridge、Arcs Runner 与平台 adapter 完成。

当前工程链路已经可用，但三平台尚未达到整体规模化准入：CSDN、知乎已有公开 URL 样本，掘金仍受平台风控和不公开/删除影响；24h/72h 样本数也尚未满足 reliability 门槛。

## 2. 前台入口与用户链路

### 2.1 发布控制塔

- 地址：`http://127.0.0.1:3027/publishing`
- 导航：工作台左侧“发布控制塔”。
- 自动刷新：每 15 秒读取 Job 与 reliability 状态。
- 展示内容：平台、Job 状态、Worker 尝试次数、reconciliation、公开 URL、首次公开时间、下次核验时间、24h/72h 指标和准入阻断项。

前台的“交给 Worker”和“排队核验”只改变耐久队列状态，不在 HTTP 请求内直接执行平台发布或浏览器核验。

### 2.2 月度生产

`/daily-execution` 中已排程且拥有正式终稿的任务会显示“机器发布”。点击后：

1. 服务端读取正式 `draft_version`。
2. 校验 `copyAllowed=true`、`testOnly=false`、Hard Rule 已通过。
3. 将不可变发布快照写入统一 Publish Job 账本。
4. 异步 dispatch 给 Worker。
5. reconciliation 获得公开 URL 后，自动写回 `content_publish_result` 和矩阵任务状态。

“回填结果（异常）”仅保留为存量兼容和异常登记入口，不是自动发布正常链路的必经步骤。

### 2.3 自由生产

`/free-production` 的确认发布不再直接调用平台发布函数，而是创建并 dispatch Publish Job。公众号正式 HTML 会携带 `wechat_html` 格式进入 Worker，避免统一队列把正式排版误当 Markdown。

公开结果出现后，系统会把 URL、发布时间、失败状态和下一步自动同步回自由生产 batch/task。

## 3. 底层实现逻辑

| 阶段 | 责任组件 | 成功依据 |
| --- | --- | --- |
| Job 创建 | Next.js API + `publish-job-service` | 已批准终稿、平台快照和幂等键持久化 |
| Worker | `workers/direct-publish-worker.mjs` | Worker 领取到期 Job；前台不直接运行 |
| 平台执行 | 既有 adapter、bridge、Arcs Runner | 平台正式动作受理，attempt 落账 |
| reconciliation | Worker + 平台只读 verify | 后台记录或公开页面可验证 |
| URL 回填 | `publish-job-backfill` | URL 写入 Publish Record、V5 月度结果或自由生产任务 |
| 存活验证 | `nextVerificationAt` 队列 | 首次公开后按 24h/72h 里程碑复验 |
| reliability | `/api/publish-reliability` | 样本数、公开转化、24h/72h、风控和重复发布共同达标 |

MCP 只是这套高层 Job 能力的另一种 Tool 调用入口，与前台 REST API 共用同一状态机；它不替代 Worker，也不会降低平台风控。

## 4. API 接线

```text
GET  /api/publish-jobs
POST /api/publish-jobs
GET  /api/publish-jobs/candidates
POST /api/publish-jobs/:id/dispatch
POST /api/publish-jobs/:id/reconcile-dispatch
GET  /api/publish-jobs/:id
GET  /api/publish-reliability
POST /api/v5/content-tasks/:taskId/publish-job
```

旧 `/api/publish-schedules/:id/run|verify` 保留兼容，但前台新链路使用异步 dispatch API，避免浏览器请求承担长任务。

## 6. 当前卡点与能力判断

1. **工程接线已完成**：3027 可以创建、查看和追踪耐久发布任务，URL 回填与 V5 两类来源同步已有代码闭环。
2. **运行依赖仍需常驻**：仅启动 3027 前台不等于 Worker 正在工作；正式环境必须按 `DEPLOYMENT.md` 同时部署 Web、bridge、Runner 和 `production-supervisor`。
3. **三平台尚未整体达标**：当前 reliability 的阻断项仍包含独立样本不足、公开转化不足以及 24h/72h 未证明。
4. **掘金是主要外部风险**：平台返回文章 ID 或短暂发布不代表稳定公开，必须以持续可访问为成功标准。
5. **安全挑战失败关闭**：验证码、登录失效和平台风控不会被自动绕过；机器会停止写入并记录阻断状态，恢复登录环境后再由 Worker 续跑核验。
