# JOTO GTM 工作台服务器正式启用前迁移与交接手册

> 适用范围：把当前本机或测试环境迁移为正式托管服务，并交接给长期负责部署、邮件和 24 小时 AI 前台采集的运维人员。
>
> 本文不保存任何真实密码、Token、邮箱授权码、OAuth Secret、数据库连接串或用户资料。所有尖括号内容都必须在实际部署环境中替换，且不得提交 Git。

## 1. 交付结论与目标架构

正式启用后，系统分为三个明确边界：

1. **GitHub**：保存应用代码、数据库迁移、扩展代码和不含秘密的部署说明。
2. **Vercel 与正式数据库**：接收普通用户请求、发送登录和通知邮件、保存任务与请求归属，不运行真实 Chrome。
3. **部署人员的 24 小时 Windows 服务器**：安装 Chrome 扩展和采集伴侣，登录中立 AI 测试账号，执行 ChatGPT、豆包、DeepSeek、千问的真实页面采集。

普通用户只负责：邮箱登录、提交产品资料、创建委托、选择 AI 平台和发送请求。普通用户不安装扩展、不配对电脑、不填写 Setup Token，也不提供 AI 平台密码、Cookie 或浏览器 Token。

## 2. 角色与责任

| 角色 | 正式启用前负责 | 正式启用后负责 | 禁止事项 |
| --- | --- | --- | --- |
| 发布负责人 | 确认 GitHub 目标提交、Vercel Production 分支和发布时间 | 管理版本发布与回滚 | 不在代码和 Issue 中粘贴秘密 |
| 数据库管理员 | 备份数据库、执行迁移、验证新增字段与索引 | 监控容量、慢查询和备份 | 不跳过备份直接迁移 |
| 邮件部署人员 | 配置安全链接、发件邮箱和 OAuth 回调 | 处理发信失败、授权过期和密钥轮换 | 不使用邮箱登录密码代替授权码或 OAuth |
| 采集服务器管理员 | 准备常开 Windows 主机、Chrome、扩展、伴侣和测试账号 | 处理离线、登录失效、扩展适配与积压 | 不让普通用户接触部署级配对码和测试账号 |
| 业务验收人员 | 模拟普通用户完成登录、委托与 AI 测试请求 | 检查结果归属、业务体验和异常提示 | 不用管理员会话代替普通用户验收 |

建议至少两个人完成正式切换：一人执行，一人逐项复核。密钥应存入团队批准的密码管理器，并设置紧急联系人和恢复流程。

## 3. 正式迁移前必须冻结的内容

在切换窗口开始前冻结以下内容，避免“代码、数据库、环境变量”来自不同版本：

- GitHub 待发布提交 SHA；
- Vercel Production Branch；
- 数据库备份时间点和备份文件校验结果；
- 正式域名及 DNS 负责人；
- 系统发件邮箱；
- Google Cloud 或 Microsoft Entra OAuth 应用；
- 24 小时 Windows 服务器设备名称、管理员和物理位置；
- Chrome 扩展目录和扩展 ID；
- 回滚负责人及允许回滚的最晚时间。

正式切换期间不要同时修改 OAuth 回调、数据库结构、域名和发件邮箱。必须按本文顺序逐项完成。

## 4. 迁移前检查清单

### 4.1 GitHub 与版本

- [ ] 工作区没有真实 `.env`、`.env.local`、Token、数据库导出或用户文件进入暂存区。
- [ ] `npm.cmd run typecheck` 通过。
- [ ] `npm.cmd run validate:structure` 通过。
- [ ] `npm.cmd run build` 通过。
- [ ] 共享采集专项测试通过：`node --test scripts/v5-ai-frontend-connections.test.mjs scripts/v5-personal-email-sender.test.mjs`。
- [ ] 发布提交包含迁移 `20260827_042_v5_deployment_shared_ai_capture.sql`。
- [ ] 发布提交包含部署人员控制台和普通用户请求面板。
- [ ] 已记录发布前 SHA 和准备发布的 SHA。

### 4.2 正式基础设施

- [ ] 正式 HTTPS 域名已经确定。
- [ ] Vercel 项目、Production 环境和正式数据库指向同一套生产资源。
- [ ] 数据库账号具备执行本次迁移的权限，但不是日常应用使用的超管账号。
- [ ] 数据库备份已经完成，并至少进行一次可读性或恢复抽查。
- [ ] 24 小时 Windows 服务器已关闭自动休眠，磁盘、电源、网络和系统时间正常。
- [ ] Windows 服务器具备受控的远程维护方式，但没有把采集伴侣端口暴露到公网。

## 5. 环境变量转移矩阵

真实值只能写入 Vercel Environment Variables、Windows 服务器上被 Git 忽略的环境文件，或团队密码管理器。

| 变量 | 放在哪里 | 如何获得 | 轮换影响 |
| --- | --- | --- | --- |
| `HOSTED_PUBLIC_BASE_URL` | Vercel | 正式 Production HTTPS Origin | 更换后需检查邮件链接和 OAuth 回调 |
| `HOSTED_REVIEW_LINK_SECRET` | Vercel | 本机生成独立随机值 | 旧的待处理确认链接可能失效 |
| `HOSTED_EMAIL_SETUP_TOKEN` | Vercel | 本机生成至少 32 字节随机值 | 只影响部署人员修改发件邮箱 |
| `HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY` | Vercel | 本机生成 32 字节随机值，建议 64 位 hex | 更换后旧 SMTP/OAuth 凭据无法解密，必须重新授权 |
| `HOSTED_EMAIL_OAUTH_REDIRECT_BASE_URL` | Vercel | 与正式工作台 HTTPS Origin 一致 | 必须同步修改供应商回调地址 |
| `HOSTED_EMAIL_GOOGLE_CLIENT_ID` / `SECRET` | Vercel | Google Cloud Web OAuth Client | Secret 轮换后必须更新 Vercel 并重新部署 |
| `HOSTED_EMAIL_MICROSOFT_CLIENT_ID` / `SECRET` | Vercel | Microsoft Entra App Registration | Secret 过期前必须提前轮换 |
| `HOSTED_CAPTURE_SETUP_TOKEN` | Vercel | 本机生成独立的至少 32 字节随机值 | 只影响部署控制台和新配对码生成 |
| `V5_WORKBENCH_BASE_URL` | Windows 服务器 | 正式工作台 HTTPS Origin | 地址错误会导致伴侣无法领取任务 |
| `V5_CAPTURE_EXTENSION_ID` | Windows 服务器 | Chrome 扩展程序页面显示的 ID | 扩展 ID 变化后伴侣会拒绝旧扩展 |
| `V5_CAPTURE_CHROME_PROFILE_DIRECTORY` | Windows 服务器，可选 | 专用 Chrome Profile 目录名 | 修改后需要重新确认所有 AI 登录状态 |

生成随机值时，每个用途单独执行一次，不得复用：

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

生成结果只复制到密码管理器和目标环境变量，不写入本文、聊天、截图、终端历史说明或 GitHub。

## 6. 数据库迁移

### 6.1 迁移前

1. 暂停正式环境的新委托和 AI 前台测试请求。
2. 记录数据库版本、字符集、时区和当前迁移最大编号。
3. 完成全量备份，并记录备份时间、位置、大小和校验结果。
4. 确认已有 `capture_pairing_codes`、`capture_devices`、`capture_tasks`、`ai_frontend_connections` 表。

### 6.2 执行迁移

按仓库既有迁移机制执行到：

```text
database/migrations/20260827_042_v5_deployment_shared_ai_capture.sql
```

迁移会完成：

- 配对码、设备和 AI 账号连接新增 `execution_scope`；
- 旧记录默认保留为 `user_private`；
- 新的部署级设备和连接使用 `deployment_shared`；
- 采集任务新增 `requested_workspace_id` 和 `requested_user_id`；
- 新增共享执行器调度和请求归属查询所需索引。

### 6.3 迁移后检查

- [ ] 三张执行器相关表都存在 `execution_scope`。
- [ ] 任务表存在 `requested_workspace_id` 和 `requested_user_id`。
- [ ] 旧数据仍为 `user_private`，没有被误改为共享执行器。
- [ ] 新增索引存在，迁移未留下半完成状态。
- [ ] 应用数据库账号仍可正常读写，但没有获得额外超管权限。

如果迁移失败，不要反复执行不确定的手工 SQL。保存错误信息，停止应用写入，使用备份恢复后再重新定位原因。

## 7. Vercel 正式环境转移

1. 打开 Vercel 项目 → **Settings → Git**，确认 Production Branch 指向批准的正式分支。
2. 打开 **Settings → Domains**，确认正式主域名和 HTTPS 状态。
3. 打开 **Settings → Environment Variables**，按第 5 节写入 Production 变量。
4. 确认数据库变量、公开域名、邮件安全链接变量属于同一套正式环境。
5. 保存环境变量后重新部署批准的 GitHub 提交。旧 Deployment 不会自动获得新变量。
6. 在 Deployment 日志中确认编译、类型检查和页面生成成功。
7. 访问正式 `/api/health`，确认返回健康状态。

不得把任何 Secret 放入 `NEXT_PUBLIC_` 变量。`NEXT_PUBLIC_` 会进入浏览器包，不能保存部署口令、OAuth Secret 或加密密钥。

## 8. 正式发件邮箱和 OAuth 转移

### 8.1 QQ、163、阿里云企业邮箱

1. 使用准备作为系统发件人的账号登录供应商官方邮箱。
2. 开启 SMTP 或第三方客户端功能。
3. 生成独立 SMTP 授权码或客户端安全密码，不使用邮箱登录密码。
4. 打开正式工作台首页，切换“我是部署人员”，进入发件邮箱连接页。
5. 填写邮箱地址、SMTP 授权码和 `HOSTED_EMAIL_SETUP_TOKEN`。
6. 页面显示“当前发件邮箱已连接”后，再进行真实邮件测试。

### 8.2 Gmail

在 Google Cloud OAuth Web Client 登记完全一致的回调地址：

```text
https://<正式域名>/api/v5/hosted/email-sender/oauth/callback/gmail
```

确认 Gmail API 已启用，并把 Client ID / Client Secret 写入 Vercel 后重新部署。若出现 `redirect_uri_mismatch`，以应用实际发出的完整回调地址为准，逐字符核对协议、域名、路径、端口和末尾斜杠。

### 8.3 Outlook / Microsoft 365

在 Microsoft Entra Web App 登记：

```text
https://<正式域名>/api/v5/hosted/email-sender/oauth/callback/outlook
```

确认 Application (client) ID、Client Secret Value 和回调地址来自同一个 App Registration。不要把 Secret ID 当作 Secret Value。

### 8.4 邮件验收

- [ ] 用一个可立即查收的普通用户邮箱请求登录链接。
- [ ] 收件箱在合理时间内收到主题含 JOTO 的邮件。
- [ ] 垃圾邮件检查完成。
- [ ] 15 分钟内打开链接，且链接只能使用一次。
- [ ] 浏览器返回正式域名，不是 `localhost` 或 `127.0.0.1`。
- [ ] 登录后工作区和用户身份正确。
- [ ] 日志和审计记录不包含 SMTP 授权码、OAuth Token 或完整 Secret。

## 9. 24 小时 Windows 采集服务器转移

### 9.1 主机准备

1. 安装项目要求的 Node.js、Chrome 和代码运行环境。
2. 使用专门的 Windows 服务账号，不使用个人日常办公账号。
3. 关闭睡眠和休眠；配置断电恢复、自动登录策略应遵守公司安全要求。
4. 将 Chrome 和项目目录纳入受控备份，但不要备份或外传浏览器 Cookie。
5. 确认本地伴侣只监听回环地址，防火墙不开放采集伴侣端口到公网。

### 9.2 安装扩展

1. Chrome 打开“扩展程序”。
2. 开启开发者模式。
3. 选择“加载已解压的扩展程序”。
4. 选择仓库中的 `browser-extension` 目录。
5. 复制 Chrome 显示的扩展 ID，写入 Windows 服务器的 `V5_CAPTURE_EXTENSION_ID`。
6. 设置 `V5_WORKBENCH_BASE_URL=https://<正式域名>`。

### 9.3 部署级配对

1. 打开正式工作台首页并切换“我是部署人员”。
2. 找到“部署一台 24h 共享 AI 采集服务器”。
3. 输入 `HOSTED_CAPTURE_SETUP_TOKEN`，点击“生成部署配对码”。
4. 在 10 分钟内把一次性配对码输入该服务器的 JOTO 扩展。
5. 运行：

```powershell
npm.cmd run capture-companion:start
```

6. 回到部署控制台，确认显示至少一台共享服务器在线。

### 9.4 AI 测试账号

只在共享服务器的专用 Chrome Profile 中登录 ChatGPT、豆包、DeepSeek、千问测试账号。建议使用专门的中立测试账号，并关闭记忆、个性化和自定义指令。

不得要求普通用户提供密码、Cookie、验证码、Token 或账号恢复信息。登录过期由采集服务器管理员处理。

### 9.5 设置开机运行

人工验收通过后再执行：

```powershell
npm.cmd run capture-companion:autostart
```

重启 Windows 服务器，确认无需人工打开项目终端也能恢复伴侣、扩展心跳和任务领取。

## 10. 普通用户端到端验收

必须使用非部署人员的普通用户邮箱，从正式域名开始完成一次真实流程：

1. 请求并打开登录邮件。
2. 选择或创建产品，提供官网或允许公开使用的资料。
3. 选择渠道和通知方式并创建委托。
4. 在“是否开启 AI 前台测试？”选择“是，发送请求”。
5. 确认页面显示共享采集服务器在线。
6. 选择一个已配置平台并发送请求。
7. 确认普通用户没有看到扩展安装、设备配对、AI 账号密码或部署级 Setup Token 输入框。
8. 刷新任务状态，确认请求进入队列并最终完成。
9. 使用第二个测试工作区尝试查询第一个用户的任务编号，应返回不存在或无权访问。

第 9 项是正式启用的阻断性验收：任务虽然由同一台共享服务器执行，但结果必须按 `requested_workspace_id` 和 `requested_user_id` 隔离。

## 11. 监控与日常运行

### 11.1 每日检查

- Vercel 健康状态和错误率；
- 登录邮件与通知邮件失败数；
- Windows 采集服务器最近心跳；
- AI 账号是否出现 `needs_login`；
- `pending` 和 `leased` 队列是否持续增长；
- 磁盘空间、Chrome 异常退出和 Windows 更新重启。

### 11.2 告警建议

- 采集设备连续 5 分钟无心跳；
- 任一平台连续多次登录失效；
- 待执行任务超过约定阈值或最长等待时间；
- 邮件连续投递失败；
- 数据库连接失败或迁移版本不一致；
- Vercel Production Deployment 回退或域名证书异常。

### 11.3 故障归属

| 现象 | 首要负责人 | 首先检查 |
| --- | --- | --- |
| 用户收不到登录邮件 | 邮件部署人员 | 发件邮箱状态、垃圾邮件、通知 Outbox |
| Google 显示 `redirect_uri_mismatch` | 邮件部署人员 | Google OAuth 回调地址与正式域名 |
| 用户页面显示共享服务器离线 | 采集服务器管理员 | Windows 电源、伴侣进程、扩展心跳、工作台地址 |
| 某一个 AI 平台不可用 | 采集服务器管理员 | 对应测试账号登录和扩展适配器 |
| 所有请求持续排队 | 采集服务器管理员 | 设备在线状态、Chrome、任务租约和队列 |
| 用户看到其他工作区结果 | 发布负责人和数据库管理员 | 立即暂停服务，检查请求归属过滤和审计日志 |

## 12. 回滚方案

### 12.1 触发条件

出现以下任一情况，应停止继续放量并评估回滚：

- 登录邮件无法稳定送达；
- 正式域名或 OAuth 回调错误导致用户无法登录；
- 数据库迁移异常或数据归属错误；
- 普通用户能够访问其他工作区任务；
- Windows 采集服务器无法稳定恢复；
- 生产构建出现阻断性错误。

### 12.2 应用回滚

1. 暂停新委托和 AI 前台测试入口。
2. 在 Vercel 回退到记录的发布前 Deployment。
3. 不要删除失败 Deployment，保留日志用于定位。
4. 确认旧版本与当前数据库结构兼容；新增的 nullable 字段可保留时，优先不做破坏性降级。

### 12.3 数据库回滚

数据库回滚只由数据库管理员执行。优先采用“停止写入、修复前滚”；只有确认新结构造成不可恢复影响时，才从迁移前备份恢复。恢复前必须记录回滚时间点和可能丢失的业务写入范围。

### 12.4 采集服务器回滚

1. 停止开机自启的采集伴侣。
2. 保留设备和连接记录用于审计，不直接删除。
3. 退出专用 AI 测试账号或撤销对应会话。
4. 普通用户界面保持“服务器离线”并给出联系部署人员提示，不引导用户自行安装工具。
