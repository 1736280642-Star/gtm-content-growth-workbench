## S — Situation：问题与影响

### 原始 Badcase

- ADP 样文以“ADP 缩写歧义”开头，开头与腾讯云 ADP 的搜索主题无关。
- GEO 调研网页、搜索需求信号和目标产品事实共用证据通道，研究材料可能被提升为产品 Claim，造成实体污染。
- 策略、检索、EvidencePack、Prompt 与正文之间缺少一个冻结的“本文为何写、回答谁、建立什么实体关系”的任务合同。
- 仅靠产品补丁或模型自评无法判断污染最早发生在哪一层，也无法保证换成其他产品后仍然有效。
- 正文生成后的本地清洗可能拆散含分号的固定文案，或在一条 EvidenceItem 对应多个 Claim 时丢失 Claim 追溯。

### 底层原因

1. **证据用途未隔离**：`research_demand`、搜索结果和 `product_fact` 没有在导入、Claim、Chunk、检索和生成各层统一拒绝越权。
2. **任务意图未冻结**：标题只是文本，没有被编译为可校验的搜索意图、主实体、答案目标、标题承诺和实体图。
3. **评测只看结果或只看链路**：只评正文会漏掉上游污染，只评链路又无法保证用户看到的文章真正好读、答题。
4. **索引版本粒度不足**：旧索引版本主要依赖来源 Hash；来源文本不变但 Claim 状态、证据用途或分块合同变化时，可能错误复用旧索引。
5. **确定性装配顺序不完整**：模型输出、固定文案、清洗、Claim 补齐和最终追溯没有形成稳定闭环。

### 对用户的影响

- 用户需要反复给单一产品打补丁，下一产品仍可能复发。
- 页面可能显示“已生成”，但文章实际上偏题、实体关系错误或事实不可追溯。
- 模型评分可能看似很高，最终硬规则仍失败；如果没有分层结果，无法知道应改研究、检索、Prompt 还是正文修复。

## T — Task：本轮增强目标与完成标准

本轮不是修一篇 ADP 文章，而是建立可复用于不同产品的生产合同与评测闭环：

`受治理来源 -> Claim/实体 -> GEO 调研 -> 策略 -> GeoArticleMission -> RAG/EvidencePack -> ProductionContract -> Prompt -> 正文 -> A/B Rubric + 事实硬规则`

### A 层 Rubric：业务链路诊断

用于回答“文章为什么会坏、最早坏在哪一层”，总分 100：

| 维度 | 权重 | 判断内容 |
| --- | ---: | --- |
| 产品与实体正确性 | 20 | 主实体一致；产品、品牌方、服务商关系完整 |
| 证据来源与用途 | 20 | 研究需求不得成为产品事实；外部实体不得串入目标产品事实 |
| GEO 目标传递 | 20 | 问题、搜索缺口、目标答案、文章角色完整 |
| 检索与 EvidencePack | 15 | 核心 Claim 有证据；EvidencePack 可生成 |
| Prompt 合同完整性 | 15 | Mission、实体图、证据边界和输出约束已注入 |
| 版本与状态一致性 | 10 | Geo Intent Hash、Entity Graph Hash、Pack 与合同一致 |

通过标准：总分 `>= 90`，每一维 `>= 80`，且无 Hard Blocker。失败时记录最早归因阶段、共同成因阶段、逃逸阶段和建议修复阶段。

### B 层 Rubric：用户端到端文章质量

用于回答“用户最终看到的文章是否达到可用质量”，总分 100：

| 维度 | 权重 | 判断内容 |
| --- | ---: | --- |
| 搜索意图与标题承诺 | 20 | 正文完整兑现标题中的问题和承诺维度 |
| 核心答案与决策价值 | 20 | 前半部分能提取明确答案，不只重复背景 |
| GEO 实体关联效果 | 20 | 目标产品、品牌归属、服务商关系正确自然 |
| 事实与证据边界 | 15 | 产品事实可追溯，无越权扩写 |
| 开头相关性与主线 | 10 | 首段直接进入目标问题，不从缩写歧义或宽泛背景开始 |
| 结构与可读性 | 10 | 结构连续、层级适中、无审计清单感 |
| 渠道表达与自然度 | 5 | 不暴露 EvidenceItem、Claim ID、JSON 等内部字段 |

通过标准：总分 `>= 90`，核心维度均 `>= 80`，无语义 Blocker。B 层通过后仍必须通过事实硬规则；两者不能互相替代。

### 总完成标准

- A 层通过。
- B 层通过。
- 标题、固定文案、实体关系、核心 Claim、Fact Trace、禁用表达等硬规则全部通过。
- 至少一篇真实模型样文可生成；本轮提高为 3 篇代表样文全部完成。
- 数据库迁移、生产镜像、健康检查、类型检查、结构检查和相关回归测试通过。
- 过程、Badcase、修复顺序、评测结果和剩余风险写入本记录。

## A — Action：修改顺序与实现

### P0：先阻断污染源

1. 新增迁移 `20260829_044_v5_geo_research_evidence_isolation.sql`，将 GEO 调研专用来源隔离出产品事实通道。
2. 导入、Claim、Chunk、检索和 EvidencePack 全链路增加 `evidenceUsage` 与 `subjectEntityIds`。
3. `research_demand` 只允许描述搜索问题、内容缺口和外部答案环境，不得成为目标产品事实。
4. 已污染数据处理结果：1 个来源被隔离；与该来源相关的 Claim 中 20 个被拒绝、23 个保持争议状态，避免自动晋升。

### P1：修正索引与检索合同

1. 索引版本改为基于完整 `manifestHash`：`auto-geo3-${manifestHash}`，覆盖来源、Claim 状态、证据用途和治理版本。
2. 分块合同升级为 `claim-aware@2`，自动知识合同升级为 `automatic-knowledge@3`。
3. 检索阶段在排序前剔除研究需求证据和外部实体证据，避免“先混入、后靠 Prompt 猜测清理”。
4. 新活动索引：`index-1a884706-bebc-415d-b841-a1e0c4b02666`，441 个文档；旧索引已 superseded。

### P2：新增产品无关的 GeoArticleMission

新增 `GeoArticleMission`，冻结：

- `primaryQuestion`、`representativeQueries`、`currentSearchGap`；
- `primaryEntityId`、目标实体图、允许和禁止的实体关系；
- `desiredAnswer`、`expectedAnswerSummary`、`titlePromiseDimensions`；
- `requiredClaimIds`、`allowedEvidenceUsages`；
- `geoIntentHash`、`entityGraphHash`。

策略、样文任务、EvidencePack 和 ProductionContract 必须复用同一 Mission 与 Hash。任何旧 Pack 或错实体 Pack 在调用正文模型前失败关闭。

### P3：重构生产合同与 Prompt

1. Prompt 明确告诉模型：搜索结果与相关文章用于理解用户搜索问题、答案环境和内容空白，目标是完成当前产品的 GEO 推广任务，不代表目标产品事实。
2. 只有 `evidenceUsage=product_fact` 且主体命中 `primaryEntityId` 的 EvidenceItem 才能写成产品事实。
3. 首段必须直接回答 `primaryQuestion`；正文前半部分需交付 `expectedAnswerSummary`；标题承诺必须全部覆盖。
4. 固定实体关系由系统按位置确定性装配，不依赖模型自行复述。
5. 产品专属写作要求仍可作为校准层存在，但不能替代全局 Mission、证据和评测合同。

### P4：建立 A/B Rubric 与三重门禁

1. 正文模型调用前执行 A 层 Rubric；链路不可靠则不生成。
2. 正文生成后执行确定性 B 层检查与独立语义评测，取两者较低分。
3. 最后执行事实硬规则；即使 A/B 均为 100，Claim 追溯或固定文案不合格仍阻断落稿。
4. A/B 结果和失败原因写入 `generation_run` 与 `draft_version`，便于页面展示和后续 Badcase 回放。

### P5：真实运行中发现并修复确定性 Badcase

按“先证据、再合同、后生成、最后表现层”的顺序，真实运行暴露并修复：

- 同一 EvidenceItem 同时支持多个必需 Claim 时，Fact Trace 从“按句去重”改为“按句 + Claim 去重”。
- 核心 Claim 补齐优先复用正文中已存在且与证据匹配的句子，避免再次插入同义句。
- 含分号的固定文案按规范化语义识别，拆句清洗后仍能完整保留。
- 模型自行生成的空格、标点变体在系统标准文案装配前移除，避免同义重复。
- 最终文本修复后再次补齐核心 Claim 并重建追溯，防止格式清洗改变句子后丢 Trace。
- GEO 确定性开头改为逐行定位，保证插入在一级标题正下方，而不是因正文缺少空行被追加到文末。

### 归因结论

本次 Badcase 不是单一 Prompt 写差，也不是只需给 ADP 增加产品规则。首因是研究证据用途与目标产品事实未隔离；共同成因是搜索意图和实体关系没有冻结进生产合同；逃逸原因是缺少 A/B 双层 Rubric 与最终事实硬规则的组合门禁。修复必须保持当前顺序：

`污染源隔离 -> 实体/证据治理 -> Mission -> 检索/EvidencePack -> Prompt -> 确定性装配 -> A/B 评分 -> 事实硬规则`

如果只改产品规则或只改 Prompt，同类问题会在其他产品上再次出现。

## 风险与后续建议

1. 新发起的 GEO 调研 v8（`geo-run-013be0ec-7728-4d13-8377-3cbc68132470`）因当前只有一个可用在线搜索 Provider，被证据门禁以 `pending_config` 阻断；系统没有降低“至少两个独立在线 Provider”的门槛。此次交付使用的是此前完成、可追溯并已编译为策略 v16 的治理结果。

3. 三篇样文当前为 `pending_review`，没有替用户执行样文内容确认；这保留了“核心判断权归用户”的产品原则。
4. 后续每次新增产品不应复制 ADP 规则，而应要求产品资料先通过实体与证据治理，再自动编译同一套 Mission、A/B Rubric 和事实硬规则。
