# 托管首次配置单页引导实现

## 结论

托管用户首次配置已收敛到首页的一条六步链路：邮箱登录、产品资料、渠道频率、通知与委托、发布账号、就绪检查。用户不需要记住多个后台入口，只需按页面编号逐步操作。

## 实现逻辑

1. 首页根据当前会话和委托状态计算唯一的当前步骤，未满足前置条件的操作保持锁定并说明原因。
2. 每一步都提供可展开的详细教程。当前步骤自动展开，已完成和未开始步骤默认收起，控制页面长度。
3. 右侧“配置通行证”汇总登录账号、产品、资料、渠道及六步状态，点击步骤可定位到对应区域。
4. “调研就绪”和“发布就绪”分开判断：创建委托后即可开始调研，发布账号可以在调研期间继续连接，避免无谓等待。
5. 知乎、CSDN、掘金的现有安全连接组件直接嵌入首页；微信公众号继续使用现有绑定能力。页面不接收 Cookie、Token、AppSecret 或平台密码。
6. 原登录页改为回到首页登录步骤，完成页和托管设置页的渠道入口也回到首页账号步骤，避免流程重新分叉。

## 底层原因

旧流程把身份验证、委托创建、通知设置和账号连接分散在多个页面。对首次使用者而言，真正的成本不是填写字段，而是不知道当前在哪、下一步去哪、哪些动作可以稍后做。单页状态机把系统内部复杂度留在实现层，只给用户呈现一条连续路径。

## 对使用者的影响

- 每个操作都有文字指引、完成标准和异常处理建议。
- 页面仍保持原有视觉语言，只新增步骤编号、折叠教程和状态通行证。
- 普通用户不会看到需要粘贴敏感凭据的表单；部署管理员的一次性配置说明单独折叠。
- 运营人员和查看者会看到权限原因与下一步，不会误以为按钮失效。

## 维护与验收

- 回归测试固定检查六个步骤、折叠教程、两个就绪状态、嵌入式账号连接和旧入口收敛。
- 页面继续复用现有托管 API 与渠道连接服务，不新增并行数据源。
- 后续若新增渠道，应扩展渠道能力和连接组件，不应再增加独立的首次配置页面。
