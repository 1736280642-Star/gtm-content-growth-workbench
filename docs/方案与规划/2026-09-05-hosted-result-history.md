# 托管步骤历史结果

## 目标与验收

- 正式托管回执的五个步骤均有结果入口；已完成结果不会因流程推进而消失。
- 结果页按步骤展示版本、留存时间、内容和确认意见，可返回回执。历史只读，不复用会过期的审核行动链接。
- 每日发布结果页可进入历史回执，明确区分当时状态与当前状态。
- Demo 与正式模式共用页面和 DTO；虚拟数据由 Demo 边界提供。

## 最简实现

复用现有只追加的 `governance_audit_event` 保存 `hosted_step_result_archived` 事件，不新增数据库或存储依赖。在审核请求创建、审核完成、每日发布批次更新的原事务内保存结果快照。读取前校验登录身份与任务所属工作空间，仅返回用户可见结果，不暴露邮箱行动令牌或内部配置。

五步分别保存资料与策略生成结果、策略确认结果、样文生成结果、样文确认结果、发布批次回执。结果由稳定 ID 指向，后续编辑只新增结果，不覆盖已有快照。旧正式任务未保存过的内容明确提示无历史快照，不拿当前内容冒充当时结果。

Demo 在生成／确认／发布时追加独立副本，浏览器刷新保留。旧浏览器数据升级只补存当前可见版本并注明来源，不清空既有操作。重置 Demo 会一并清空历史，这是显式的场景重置。

## 验证与影响

测试五步入口、只读历史、版本切换、修改意见、历史内容不随最新内容改变、任务隔离、旧数据兼容、缺失结果反馈，以及原托管确认流程。运行类型、结构、月度命名及托管与 Demo 回归检查。

对用户：仍从原回执按原流程操作，多一个可回看的记录入口。对维护：复用既有事务和审计存储，不增加迁移步骤；历史读取不触发调研、审批、发布或邮件。

## 复盘与边界

- 不能把已过期的审核链接当成结果存档；只读结果使用任务权限及稳定结果 ID，与审核操作令牌分离。
- 不能用当前策略／当前正文重建“当时结果”；生成和确认分别留存副本。旧 Demo 补存明确标注，且不伪造历史确认决定。
- 发布回执冻结当时的状态与 URL，外部公开文章本身仍可能被平台修改；结果页明确提示这一点。
- Demo 重置或清除浏览器站点数据会移除本地历史。未改变 `main`、未重新创建独立 Demo 前端；本次发布范围限定为 `codex/demo-runtime`，不合并到 `main`。
