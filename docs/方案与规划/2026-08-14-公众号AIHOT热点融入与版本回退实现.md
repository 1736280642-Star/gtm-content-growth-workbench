# 公众号 AIHOT 热点融入与版本回退实现

## 结论

公众号正文预览已接入 AIHOT 最新精选。系统不为不同内容类型编写热点策略分支，而是把当前内容类型的完整版本规则、当前正文、产品证据和热点候选一起交给正文模型。模型负责判断是否适合、选择热点、形成写作角度和声明改写章节；代码负责数据真实性、确定性校验和版本管理。

## 实现逻辑

1. 用户在正文预览点击“加入热点”，服务端通过 AIHOT API v1 读取最近 24 小时精选并使用 ETag 保存本地缓存。
2. 模型输入包含完整 `FreeContentExpressionTypeVersion`、当前正文、产品知识、品牌边界、热点候选及已排除热点，不存在按内容类型硬编码的 `if/else` 策略。
3. 模型输出统一的热点融入计划：热点 ID、相关度、选择原因、写作角度、受影响章节、风险提示、标题、摘要和新章节。
4. 服务端确认热点来自真实候选池、相关度达到通用门槛、章节属于当前内容类型，并复用公众号正文确定性校验。
5. 只有模型声明的章节会被替换，其他章节保留；热点条目以 `trend_signal` 来源保存 AIHOT 与第三方原文入口。
6. 成功结果创建新的 `ContentDraftArtifact`，通过 `previousArtifactId` 连接上一版本。更换热点会排除已尝试热点；恢复操作只切换当前版本指针，不删除历史产物。

## 底层原因

- 内容类型本身已经包含目标、受众、结构、表达、推广和证据规则，让模型读取正式版本比维护多套热点策略更轻且更一致。
- 热点属于有时效性的选题信号，不是 JOTO 产品事实。独立 `trend_signal` 可以防止热点摘要污染产品知识与 GEO EvidencePack。
- 局部改写和版本指针避免热点操作破坏已确认正文，并让用户可以连续更换或逐级返回。
- ETag 与最近成功缓存降低重复请求，也保证外部服务短暂失败时正文链路不会被覆盖或清空。

## 对使用者的影响

- 用户不需要先浏览热点库或填写额外表单，一次点击即可让模型完成选择与融入。
- 第一次成功后按钮变为“更换热点”，同时出现“返回上一版本”。
- 正文页会展示模型为什么选择、采用什么角度、影响哪些章节以及可追溯来源。
- 如果没有自然相关热点、模型结果越界或外部数据不可用，系统保持当前正文不变并说明下一步。

## 验证与维护

- 运行 `node --no-warnings --experimental-transform-types --loader ./workers/typescript-loader.mjs --test scripts/v5-aihot-hotspot-integration.test.mjs` 验证 API v1 字段、完整内容类型上下文、模型输出协议和页面操作入口。
- 运行 `npm.cmd run typecheck`、`npm.cmd run validate:structure` 与 `npm.cmd run validate:monthly-naming` 完成项目门禁。
- AIHOT 字段升级时只修改 `aihot-trend-service.ts` 适配器，不把外部字段扩散到正文页面和模型协议。
