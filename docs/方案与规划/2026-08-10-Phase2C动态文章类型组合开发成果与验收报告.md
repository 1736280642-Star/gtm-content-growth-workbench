# Phase 2C 动态文章类型组合开发成果与验收报告

> 日期：2026-08-10  
> 当前结论：工程、迁移与 MySQL 原子事务验收通过；WorkBuddy 真实组合等待 Phase 2B 真实证据包

## 1. 结论

产品 GEO 策略包现在可以携带 2-6 种有完整定义的文章类型。智谱在内部调研综合阶段读取现有已激活类型，按语义选择 `matched`、`adapted` 或 `generated`，并输出定义、适用/不适用问题、结构、重点、风格、篇幅、证据偏好、CTA、渠道、问题簇、推荐理由和证据准备度。

AI 只生成候选草稿。用户在产品策略页一次勾选并确认后：

- `matched` 引用版本被冻结；
- `adapted/generated` 产品级版本被激活；
- 未选择版本被拒绝；
- 策略包当前引用、文章类型版本与审计在同一个 MySQL 事务中提交。

## 2. 实现逻辑、底层原因和用户影响

### 2.1 AI 语义决策

智谱综合 Prompt 会收到当前激活文章类型的完整语义定义。它不能只按名称/关键词匹配，而要为问题簇选择：

- `matched`：现有版本直接适配；
- `adapted`：方向适配，但要形成产品级新版本；
- `generated`：现有类型均不适配，生成新草稿。

底层原因：文章类型决定后续 Prompt 的结构和表达重点，不能只是文章标签。

用户影响：用户看到“为什么推荐、适合什么、不适合什么、怎么写”，不需要进入高级类型管理页逐条发布。

### 2.2 确定性契约门禁

策略编译会阻断：

- 少于 2 种或多于 6 种；
- 类型 ID/版本重复；
- 缺定义、内容目标、推荐理由；
- 没有结构模块；
- matched 缺正式引用；
- adapted 缺基础版本；
- 篇幅范围非法。

底层原因：模型返回 JSON 不代表规则可生产，必须由代码验证。

用户影响：不完整的新类型不会进入策略确认，也不会污染正式批量生成。

### 2.3 策略确认与类型发布原子化

新增 `product_strategy_article_type_versions` 保存产品策略级文章类型草稿。编译策略不会激活任何类型；只有 Human actor 的策略确认事务能够改变状态。确认事件还冻结选择集合与 `decision_payload_hash`，同一幂等键换一组选择会被拒绝。

底层原因：原有文章类型状态在 JSON 文件，无法和 MySQL 策略确认构成真实数据库事务。产品级冻结版本必须落入同一正式数据域。

用户影响：不会出现“策略确认失败但某个 AI 新类型已经生效”的半成功状态。

### 2.4 月度配额派生

`deriveProductStrategyMonthlyTypeQuotas` 使用最大余数法从已确认组合和建议占比确定性派生整数篇数。证据状态为 `blocked` 的类型不分配数量，结果只作为现有 `MonthlyPlan` 的类型配额输入，不创建新的计划周期。
