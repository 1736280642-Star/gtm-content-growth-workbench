# GEO 托管邮件与安全链接配置指南

## 结论

GEO 托管邮件需要先完成所有部署共用的安全链接配置，再从两条邮件投递链路中选择一条：

1. **内置发件邮箱（推荐用于当前部署）**：QQ、163、阿里云企业邮箱使用 SMTP 授权码；Gmail、Outlook 使用供应商 OAuth。
2. **外部 Mail Relay**：已有企业邮件 API 或自建邮件适配器时使用。

两条邮件链路不要同时配置。只要 `HOSTED_EMAIL_DELIVERY_URL` 和 `HOSTED_EMAIL_DELIVERY_TOKEN` 同时存在，系统就优先使用 Mail Relay；要改用内置发件邮箱，应同时清空这两个字段。

生产环境至少必须具备：

- 可被外部用户访问的 `HOSTED_PUBLIC_BASE_URL`；
- 独立生成的 `HOSTED_REVIEW_LINK_SECRET`；
- 一条已经连接并通过真实邮件验收的投递链路。

缺少邮件配置时，通知 Outbox 会保持待配置或可重试状态，不会伪造“已发送”。`http://127.0.0.1:3027` 只适合本机验收，不能出现在发给外部用户的邮件链接中。

## 1. 先选择邮件投递链路

| 你的情况 | 选择 | 需要填写的字段 | 获取入口或方式 |
| --- | --- | --- | --- |
| 只有一个可用于系统发信的邮箱 | 内置发件邮箱 | Setup Token、加密密钥，以及对应邮箱的 SMTP/OAuth 字段 | 使用本文第 3～6 节的官方入口 |
| 已有符合接口契约的企业邮件 API | 外部 Mail Relay | `HOSTED_EMAIL_DELIVERY_URL`、`HOSTED_EMAIL_DELIVERY_TOKEN` | 向企业邮件平台管理员索取服务端接口地址和 Token |
| 只有供应商 SMTP 或专有 REST API | 自建 Mail Relay | Relay URL、本机生成的 Relay Token、供应商凭据 | 按第 7 节部署适配器；供应商凭据只保存在适配器侧 |

> 不要把 Gmail/Outlook 登录密码当 OAuth Client Secret，也不要把 QQ/163 邮箱登录密码当 SMTP 授权码。

## 2. 所有链路共用：安全链接配置

### 2.1 字段清单

| 字段 | 值从哪里来 | 具体操作 | 访问入口 |
| --- | --- | --- | --- |
| `HOSTED_PUBLIC_BASE_URL` | 工作台 Production 主域名 | 打开 Vercel 项目 → **Settings → Domains**，复制用户实际访问的主域名，只保留 `https://域名`，末尾不要加 `/` | [打开 Vercel Dashboard](https://vercel.com/dashboard) |
| `HOSTED_REVIEW_LINK_SECRET` | 部署人员在本机随机生成 | 在项目终端执行下方命令；每个部署独立生成一次 | 无需申请，使用本节命令生成 |

生成链接签名密钥：

```powershell
node -e "process.stdout.write(require('node:crypto').randomBytes(48).toString('base64url'))"
```

写入本地 `.env` 或 Vercel 环境变量：

```dotenv
HOSTED_PUBLIC_BASE_URL=https://workbench.example.com
HOSTED_REVIEW_LINK_SECRET=<上一步生成的随机值>
```

线上写入路径：打开 [Vercel Dashboard](https://vercel.com/dashboard) → 选择当前项目 → **Settings → Environment Variables**。至少勾选 Production，保存后重新部署；环境变量不会自动作用于旧 Deployment。详细规则见 [Vercel Environment Variables 官方文档](https://vercel.com/docs/environment-variables)。

### 2.2 安全要求

- `HOSTED_PUBLIC_BASE_URL` 必须是外部用户可访问的 HTTPS Origin，不填写 `localhost`、`127.0.0.1`、内网管理地址或邮件接口地址。
- `HOSTED_REVIEW_LINK_SECRET` 不得复用数据库密码、模型 API Key、渠道 Cookie、Setup Token 或邮件 Token。
- 不要把生成结果写进本文、聊天、截图、Issue 或 Git 提交。
- 轮换 `HOSTED_REVIEW_LINK_SECRET` 会让此前生成且尚未使用的行动链接失效，应先检查待处理确认邮件，再安排轮换和补发。

## 3. 内置发件邮箱：部署共用字段

### 3.1 字段清单与生成方式

| 字段 | 是否必需 | 值从哪里来 | 获取入口或方式 |
| --- | --- | --- | --- |
| `HOSTED_EMAIL_SETUP_TOKEN` | 必需 | 工作台自己生成的部署管理口令 | 在项目终端执行下方 base64url 命令 |
| `HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY` | 必需 | 工作台自己生成的 32 字节加密密钥 | 在项目终端执行下方 hex 命令 |
| `HOSTED_EMAIL_OAUTH_REDIRECT_BASE_URL` | Gmail/Outlook 必需 | 与 `HOSTED_PUBLIC_BASE_URL` 相同的正式 HTTPS Origin | [打开 Vercel Dashboard](https://vercel.com/dashboard) → Project → Settings → Domains |

生成 Setup Token：

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

生成 32 字节凭据加密密钥（输出 64 位 hex）：

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

写入部署环境：

```dotenv
HOSTED_EMAIL_SETUP_TOKEN=<第一条命令的输出>
HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY=<第二条命令的输出>
HOSTED_EMAIL_OAUTH_REDIRECT_BASE_URL=https://workbench.example.com
```

三个字段分别承担管理员门禁、数据库凭据加密和 OAuth 返回地址，不能互相替代。加密密钥一旦更换，此前保存的 SMTP/OAuth 凭据将无法解密，必须重新连接发件邮箱。

## 4. Gmail：获取 OAuth Client ID 与 Client Secret

Gmail 不填写 SMTP 授权码。当前工作台使用 Google OAuth，仅申请 `openid`、`email` 和 `gmail.send`，用于识别授权账号并发送邮件，不申请读取收件箱。

### 4.1 官方入口

- [Google Cloud Console](https://console.cloud.google.com/)
- [启用 Gmail API](https://console.cloud.google.com/apis/library/gmail.googleapis.com)
- [Google Auth Platform Branding](https://console.cloud.google.com/auth/branding)
- [Google Auth Platform Audience](https://console.cloud.google.com/auth/audience)
- [Google Auth Platform Clients](https://console.cloud.google.com/auth/clients)
- [Google 官方 OAuth Client 说明](https://support.google.com/cloud/answer/15549257)

### 4.2 逐步操作

1. 打开 [Google Cloud Console](https://console.cloud.google.com/)，在顶部项目选择器中选择当前部署自己的项目；没有项目时先创建。不要使用其他部署人员带具体 `project=` 参数的链接。
2. 打开 [Gmail API 页面](https://console.cloud.google.com/apis/library/gmail.googleapis.com)，确认顶部仍是同一个项目，点击 **Enable/启用**。
3. 打开 [Branding](https://console.cloud.google.com/auth/branding)，填写应用名称、用户支持邮箱和开发者联系邮箱。
4. 打开 [Audience](https://console.cloud.google.com/auth/audience)：
   - 只允许同一 Google Workspace 组织使用时选 Internal；
   - 需要普通 Gmail 或组织外账号授权时选 External，并先把测试邮箱加入 Test users。
5. 打开 [Clients](https://console.cloud.google.com/auth/clients)，点击 **Create client**，Application type 选择 **Web application**。
6. 在 **Authorized redirect URIs** 添加完全一致的回调地址：

   ```text
   https://<正式域名>/api/v5/hosted/email-sender/oauth/callback/gmail
   ```

   本机验收另加：

   ```text
   http://127.0.0.1:3027/api/v5/hosted/email-sender/oauth/callback/gmail
   ```

7. 创建后复制 **Client ID** 和 **Client secret**。Secret 只写入服务端环境变量，不得放入 `NEXT_PUBLIC_` 字段。
8. 在 Vercel Project → Settings → Environment Variables 写入：

   ```dotenv
   HOSTED_EMAIL_GOOGLE_CLIENT_ID=<Google Client ID>
   HOSTED_EMAIL_GOOGLE_CLIENT_SECRET=<Google Client secret>
   ```

9. 保存并重新部署最新的 `main`。回到首页 → **我是部署人员 → 连接系统发件邮箱**，输入 Gmail 地址和 Setup Token，点击 **前往 Google 授权**。
10. 只在 Google 官方页面选择发件账号并同意授权。返回工作台后必须看到“当前发件邮箱已连接”。

## 5. Outlook：获取 Microsoft Client ID 与 Client Secret

Outlook 不填写 SMTP 授权码。当前代码使用 Microsoft `consumers` OAuth 端点，面向 Outlook.com、Hotmail、Live 和 MSN 等个人 Microsoft 账号，申请 `Mail.Send`、`User.Read`、`offline_access`、`openid` 和 `email`。

> 当前实现不是通用 Microsoft 365 企业租户 OAuth。自定义企业域若属于 Microsoft 365，应先把代码端点从 `consumers` 扩展为经评审的 `organizations` 或 `common` 流程，再按企业租户策略授权；仅在后台创建 App registration 不能绕过这一代码限制。

### 5.1 官方入口

- [Microsoft Entra App registrations](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade)
- [Microsoft 官方应用注册说明](https://learn.microsoft.com/en-us/graph/auth-register-app-v2)
- [Microsoft 官方 Client Secret 说明](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-credentials)

### 5.2 逐步操作

1. 打开 [Microsoft Entra App registrations](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade)，点击 **New registration**。
2. 填写应用名称。若按当前个人 Outlook 链路使用，Supported account types 应包含 **Personal Microsoft accounts**。
3. 注册完成后，在 Overview 复制 **Application (client) ID**。不要复制 Object ID。
4. 打开 **Authentication → Add a platform → Web**，添加回调地址：

   ```text
   https://<正式域名>/api/v5/hosted/email-sender/oauth/callback/outlook
   ```

   本机验收另加：

   ```text
   http://127.0.0.1:3027/api/v5/hosted/email-sender/oauth/callback/outlook
   ```

5. 打开 **API permissions → Add a permission → Microsoft Graph → Delegated permissions**，核对 `Mail.Send` 和 `User.Read`。OAuth 流程还会请求 `offline_access`、`openid` 和 `email`。
6. 打开 **Certificates & secrets → Client secrets → New client secret**，创建后立即复制 **Value**。不要误填 Secret ID；离开页面后 Value 不会再次完整显示。
7. 在 Vercel 环境变量写入：

   ```dotenv
   HOSTED_EMAIL_MICROSOFT_CLIENT_ID=<Application client ID>
   HOSTED_EMAIL_MICROSOFT_CLIENT_SECRET=<Client secret Value>
   ```

8. 保存并重新部署。回到首页部署人员面板，输入 Outlook/Hotmail 地址和 Setup Token，点击 **前往 Microsoft 授权**。
9. 只在 Microsoft 官方页面选择账号并同意。返回工作台后检查“当前发件邮箱已连接”。

## 6. QQ、163、阿里云企业邮箱：获取 SMTP 授权码

这些邮箱不需要 Google/Microsoft OAuth Client。用户填写的是邮箱供应商生成的 SMTP 授权码或三方客户端安全密码，不是网页登录密码。

### 6.1 QQ 邮箱

官方入口：[QQ 邮箱网页版](https://mail.qq.com/)

1. 使用准备作为系统发件人的 QQ 邮箱登录 [mail.qq.com](https://mail.qq.com/)。
2. 打开 **设置 → 账号与安全 → 安全设置**。
3. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务**。
4. 开启 SMTP 相关服务，按手机或账号安全验证要求操作。
5. 点击 **生成授权码**，复制生成结果。
6. 回到工作台发件邮箱授权页，把该值填入 **SMTP 授权码**；不要填写 QQ 登录密码。

QQ 邮箱目前没有稳定的、对所有账号通用的设置深链，因此文档链接到官方登录页，并给出登录后的完整路径。

### 6.2 163 邮箱

官方入口：[163 邮箱网页版](https://mail.163.com/)

1. 使用准备作为系统发件人的 163 邮箱登录 [mail.163.com](https://mail.163.com/)。
2. 打开 **设置 → POP3/SMTP/IMAP**。
3. 开启 **IMAP/SMTP** 或 **POP3/SMTP** 服务。
4. 按页面安全验证要求创建 **客户端授权密码**。
5. 回到工作台，把客户端授权密码填入 **SMTP 授权码**。

163 邮箱设置页依赖登录会话，没有稳定的公开深链，因此从官方网页版进入最可靠。

### 6.3 阿里云企业邮箱

官方入口：[阿里云“三方客户端安全密码”操作说明](https://help.aliyun.com/zh/document_detail/444380.html)

1. 管理员使用 postmaster 登录阿里邮箱管理后台。
2. 按官方文档打开 **安全管理 → 账号安全 → 访问策略**，允许目标账号使用第三方客户端；策略变更可能需要数分钟生效。
3. 开启三方客户端安全密码策略并设置生效范围。
4. 发件账号本人登录阿里邮箱网页版，打开 **设置 → 更多设置 → 账户与安全 → 账户安全**。
5. 生成三方客户端安全密码，填写设备名称并点击确认；只复制但不确认，密码不会生效。
6. 把生成时显示的安全密码填入工作台 **SMTP 授权码**。

阿里云官方说明：安全密码只在生成时完整显示，管理员不能代替员工查看或生成子账号安全密码。SMTP 地址为 `smtp.qiye.aliyun.com`，SSL 端口为 `465`。

## 7. 外部 Mail Relay：四项配置与接口契约

使用外部 Mail Relay 时写入：

```dotenv
HOSTED_PUBLIC_BASE_URL=https://workbench.example.com
HOSTED_REVIEW_LINK_SECRET=<本机生成的随机值>
HOSTED_EMAIL_DELIVERY_URL=https://mail-relay.example.com/send
HOSTED_EMAIL_DELIVERY_TOKEN=<邮件接口提供或本机生成的随机值>
```

### 7.1 每个字段从哪里获得

| 字段 | 获取方式 | 注意事项 |
| --- | --- | --- |
| `HOSTED_EMAIL_DELIVERY_URL` | 向企业邮件 API 管理员索取，或使用自己部署的适配器公开 `POST /send` 地址 | 没有通用领取网站；该值属于你选择的邮件系统 |
| `HOSTED_EMAIL_DELIVERY_TOKEN` | 使用企业 API 提供的服务端 Token，或用下方命令为自建适配器生成 | 不得使用邮箱密码；工作台和适配器必须配置同一个值 |

生成自建 Relay Bearer Token：

```powershell
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('base64url'))"
```

`HOSTED_EMAIL_DELIVERY_URL` 必须能从 `workbench-web` 和托管 Worker 所在容器访问。宿主机适配器可使用 `http://host.docker.internal:<port>/send`；跨机器或互联网访问必须使用 HTTPS。

### 7.2 工作台发送的 HTTP 请求

```http
POST /send
Authorization: Bearer <HOSTED_EMAIL_DELIVERY_TOKEN>
Content-Type: application/json
x-idempotency-key: <通知任务ID>
```

请求体：

```json
{
  "to": "user@example.com",
  "subject": "邮件标题",
  "text": "纯文本正文",
  "html": "<p>HTML 正文</p>",
  "idempotencyKey": "notification-task-id"
}
```

成功响应使用 HTTP 2xx，并建议返回供应商消息 ID：

```json
{
  "messageId": "provider-message-id"
}
```

也可以返回 `id`。没有消息 ID 时工作台会记录 `accepted`，但生产适配器仍应保存供应商回执，方便定位退信和重复投递。

### 7.3 Relay 必须完成的安全检查

1. 使用常量时间比较验证 Bearer Token；
2. 使用 `x-idempotency-key` 或请求体 `idempotencyKey` 防止同一通知重复发送；
3. 校验收件邮箱、标题、文本、HTML，并限制请求体大小；
4. 不在日志中记录 Token、完整正文或用户隐私；
5. 把供应商拒绝、超时和限流转换为非 2xx，交给工作台重试；
6. 把供应商 API Key 只保存在 Relay 或秘密管理服务，不传给工作台前端。

## 8. Docker 3027 与 Vercel 写入方式

### 8.1 本地 Docker

首次部署从模板创建 `.env`；已有 `.env` 时只补充字段，不覆盖数据库密码和其他配置。

```powershell
Copy-Item .env.example .env
```

人工填写后重新构建：

```powershell
npm.cmd run docker:3027:deploy -- -NoOpen
```

只检查变量是否存在，不打印实际值：

```powershell
docker compose exec -T workbench-web node -e 'for (const key of ["HOSTED_PUBLIC_BASE_URL","HOSTED_REVIEW_LINK_SECRET","HOSTED_EMAIL_SETUP_TOKEN","HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY"]) console.log(`${key}=${process.env[key]?.trim()?"SET":"UNSET"}`)'
```

如果选择 Relay，把检查列表中的后两项替换为 `HOSTED_EMAIL_DELIVERY_URL` 和 `HOSTED_EMAIL_DELIVERY_TOKEN`。

### 8.2 Vercel

1. 打开 [Vercel Dashboard](https://vercel.com/dashboard)。
2. 选择当前项目 → **Settings → Environment Variables**。
3. 按本文选择的链路逐个粘贴变量名和值，至少勾选 Production。
4. Secret 字段不要使用 `NEXT_PUBLIC_` 前缀。
5. 保存后打开 Deployments，重新部署最新的 `main`。旧 Deployment 不会自动获得新值。
6. 生产域名变化时，同时更新 `HOSTED_PUBLIC_BASE_URL`、`HOSTED_EMAIL_OAUTH_REDIRECT_BASE_URL` 和供应商后台登记的回调 URI。

## 9. 端到端验收

### 9.1 内置发件邮箱验收

1. 打开首页，切换到 **我是部署人员**。
2. 检查安全参数已经写入并完成重新部署。
3. 点击 **现在连接发件邮箱**。
4. 输入完整邮箱地址，确认系统自动识别到正确供应商。
5. QQ/163/阿里云填写 SMTP 授权码；Gmail/Outlook 点击供应商 OAuth。
6. 填写与部署环境完全相同的 Setup Token。
7. 授权完成后检查页面顶部显示“当前发件邮箱已连接”。
8. 切回普通用户，向一个可以立即查收的工作邮箱发送登录链接。
9. 检查收件箱和垃圾邮件，在 15 分钟内打开链接；页面应自动回到已登录状态。

### 9.2 Relay 验收

1. `HOSTED_EMAIL_DELIVERY_URL` 和 `HOSTED_EMAIL_DELIVERY_TOKEN` 必须同时为 `SET`；只填一项会进入失败关闭状态。
2. 从 `workbench-web` 容器确认 Relay 地址可访问，但不要在命令中打印 Token。
3. 触发真实测试通知，供应商应返回消息 ID，Outbox 从待处理进入 `sent`。
4. 重复处理同一 Outbox 任务不得发送第二封邮件。

### 9.3 安全链接验收

1. 邮件中的确认链接可以在没有工作台登录会话的浏览器中打开；
2. 链接必须使用正式 HTTPS 域名；
3. 人工修改签名或 Token 后必须被服务端拒绝；
4. 链接过期后必须给出明确原因和重新获取方式；
5. 不得在应用日志中出现完整行动 Token、邮箱授权码、OAuth Refresh Token 或邮件正文。

## 10. 常见错误与下一步

| 现象 | 常见原因 | 下一步 |
| --- | --- | --- |
| Google 提示 `redirect_uri_mismatch` | Google Client 中登记的回调地址与工作台实际地址不完全一致 | 到 [Google OAuth Clients](https://console.cloud.google.com/auth/clients) 核对协议、域名、路径和末尾斜杠 |
| Gmail 授权后没有 Refresh Token | 未重新显示同意页，或应用仍处于测试限制 | 从工作台重新发起授权；检查 [Audience](https://console.cloud.google.com/auth/audience) 的 Test users |
| Microsoft 提示回调地址错误 | App registration 的 Web Redirect URI 不一致 | 到 [Microsoft App registrations](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade) → Authentication 核对 `/outlook` 回调 |
| Microsoft 个人账号无法登录 | Supported account types 未包含个人 Microsoft 账号 | 修改 App registration 的账号类型后重新授权 |
| Microsoft 365 企业账号无法登录 | 当前代码使用 `consumers` 端点 | 先完成企业租户 OAuth 代码改造，不要反复更换 Secret |
| QQ/163 SMTP 验证失败 | 填了登录密码、SMTP 未开启或授权码失效 | 回到官方邮箱设置重新开启服务并生成授权码 |
| 阿里邮箱验证失败 | 域管仍禁止三方客户端，或生成后未点击确认 | 按[阿里云官方说明](https://help.aliyun.com/zh/document_detail/444380.html)检查访问策略和安全密码状态 |
| 页面提示 Setup Token 未配置 | 部署环境没有 `HOSTED_EMAIL_SETUP_TOKEN`，或修改后未重建 | 在本地 `.env` 或 Vercel Environment Variables 写入并重新部署 |
| 以前的 SMTP/OAuth 凭据突然无法使用 | 更换了 `HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY` | 使用当前加密密钥重新连接发件邮箱 |
| Relay 配置不完整 | URL 与 Token 只填了一项 | 两项同时配置，或两项同时清空后改用内置发件邮箱 |

## 11. 安全、轮换与故障影响

- `.env`、`.env.local`、真实 Token、Secret、API Key、Cookie、邮箱密码和未脱敏私有链接不得提交 GitHub。
- Gmail/Microsoft Client Secret、SMTP 授权码和 OAuth Refresh Token 只保存在服务端；不要写入 `NEXT_PUBLIC_` 环境变量。
- 轮换 `HOSTED_EMAIL_DELIVERY_TOKEN` 时，先更新 Relay，再更新工作台并重新部署，避免通知在切换窗口持续失败。
- 轮换 `HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY` 前必须安排所有发件邮箱重新授权。
- 邮件服务暂时不可用时，系统保留 Outbox 和失败原因；用户影响是通知延迟，不应绕过确认门禁继续正式发布。
- Google、Microsoft 或邮箱供应商控制台入口可能随产品改版调整；优先使用本文列出的官方入口，不使用第三方“代生成授权码”网站。
