# V5 自由内容生产实现记录

## 结论

自由内容生产采用独立的表达预设入口，不再复制月度内容矩阵的配置表单。用户只需要选择或新建表达、查看单篇正文、就地补齐风险、确认一次自动发布；月份归属、产品规则、知识快照、渠道与发布配置由系统承担。

## 实现逻辑

1. 五类系统表达以版本化 JSON 种子维护，自定义表达必须继承其中一类，不能覆盖品牌基线、事实门禁与渠道安全规则。
2. 选择表达后编译 `ExpressionPlan`，冻结产品规则、知识、品牌基线、表达版本与补充事实，再生成 `ContentDraftArtifact`。
3. 输出先经过确定性校验；可修复结构问题最多自动修复一次，事实或合规风险直接阻断。
4. 缺失事实在正文同页按白名单字段补充，只重生成受影响章节，随后执行全文复检。
5. 发布前校验正文摘要、风险快照、必需素材、账号连接与权限，并移除视觉占位和内部批注。
6. 发布成功后以 `planningSource = free_production` 回写所属月份的 `MonthlyPlan`，不建立第二套计划或复盘周期。

## 底层原因

- 表达预设是用户真正需要做的业务选择，产品、知识、受众、标题、渠道和发布方式属于系统配置，不应重复暴露。
- 版本与快照保证正文、风险和发布结果可追溯，避免配置变化后无法解释历史产物。
- 正文摘要校验和幂等键分别防止“确认后正文被替换”和“重复点击产生重复任务或重复发布”。
- 局部重生成降低补充事实对已确认章节的扰动，全文复检避免局部变更绕过整体安全门禁。

## 对使用者的影响

- 首屏从多字段生产表单缩短为五类表达列表。
- 新表达在当前页抽屉完成，保存后直接生成，不跳转配置页。
- 正文与风险并排呈现；移动端先阅读正文，再处理风险。
- 发布只有一次人工确认，但任何事实、素材、权限或连接问题都会给出原因和下一步。

## 复盘与维护

- 运行时批次、工作区自定义表达和上传素材均被 Git 忽略；系统表达种子可以评审和版本化。
- 正式发布适配器必须把本地素材引用转换为渠道可识别的媒体 ID；不能转换时应保持阻断，不能伪造成功。
- 新增表达基础类型时，必须同步更新预设键、种子、测试和结构校验。当前阶段固定为五类，避免无收益扩张。
