## 结论与边界

Demo 复用 main 的页面、组件、CSS 和跳转规则，只替换数据与外部执行。不是另一套展示页面。

## 怎么打开

在项目目录运行以下命令。不需要数据库、模型凭证、真实邮箱或企业知识库。

```powershell
npm.cmd run build:demo
npm.cmd run start:demo
```

打开 [工作台首页](http://127.0.0.1:3064/)。已有构建时只运行第二条。

- [演示控制台与收件箱](http://127.0.0.1:3064/demo-control)
- [每日结果邮件](http://127.0.0.1:3064/hosted/email?orderId=demo-order-orbitdesk)
- [公众号生产结果](http://127.0.0.1:3064/free-production?batch=demo-free-ready)
- [内容监控](http://127.0.0.1:3064/content-monitor?tab=content)

修改代码时可用 `npm.cmd run dev:demo`。面试演示建议使用正式构建，避免开发模式热更新与重新编译造成等待。普通 `npm run build` 的生产模式保持原逻辑；请勿用它启动演示。

## 8 分钟演示路线

1. 从首页说明用户委托：邮箱、产品资料、渠道、人工判断点。
2. 打开 HarborFlow 策略邮件，修改核心表达并确认；再打开样文邮件确认正文。
3. 查收 HarborFlow 结果邮件，打开关联的公开文章（本地模拟），再进入内容监控核对同一条结果。
4. 查收 OrbitDesk 结果邮件：默认 6 项计划中，3 项已发布、2 项审核或顺延、1 项需补资料。每篇已发布正文均可打开，不能只停留在成功提示。
5. 进入公众号内容生产：选类型、填写表达重点、生成正文、查看来源、选封面、改正文与排版，最后发送到模拟草稿箱。草稿箱状态不等同于正式发布。
6. 查看产品知识库、研究运行、问题目录、规则包和监控指标，解释资料怎样流入生成和评估。
7. 控制台切换“异常处理”，补充虚拟资料后查看任务恢复。
8. 切换“月末复盘”，展示完成结果、合成指标与后续建议。

## 场景与页面结果

| 场景 | 起点与明确结果 |
| --- | --- |
| 完整结果 | 默认登录；产品资料、研究结果、正文、发布记录、邮件与监控可立即查阅 |
| 首次使用 | 未登录；填 `presenter@example.com` 后，从演示收件箱打开登录邮件，继续原首页流程 |
| 异常处理 | 缺少资料；知识库待办、生产异常和邮件提示对应同一项任务，补充后恢复 |
| 月末复盘 | 本月任务完成；已发布正文和指标可查，复盘建议有具体内容 |

控制台提供 64 个原页面入口及 17 个关键子视图的清单。原 main 已合并或重定向的页面继续跳到同一目的页，不额外制造一套旧页面。例如旧月度入口进入内容自动化，旧复盘入口进入监控的 AI 视图。

部分原页面默认打开新建表单（例如规则包）；已有虚拟结果在原来的“已有规则包”标签中。正文编辑页的内容在输入框内，不应拿页面静态文本为空当作正文不存在。

## 实现逻辑、原因与使用者影响

- **同一前端**：根布局按构建模式挂载 `DemoBoundary`，main 页面和样式不复制。原因是复制页面会再次偏离主流程；用户看到的导航、输入和结果结构保持一致。
- **同一组关联数据**：产品、委托、任务、正文、邮件和监控共用浏览器状态图。读页面是数据投影，写操作更新同一条记录，因此邮件数量、正文链接和监控结果能够对上。
- **确定的模拟执行**：生成、授权、发送和采集返回预设且可复现的虚拟结果。人工确认、修改、失败恢复、版本冲突和幂等约束仍保留；未适配调用明确失败，不伪装成功。
- **浏览器隔离**：状态保存在当前浏览器的 localStorage，刷新与同源多标签页可继续；不同浏览器互不影响。不需要共享演示数据库，代价是不能跨设备同步操作记录。
- **图片仍跟随状态**：图片请求不经过浏览器 fetch；边界层把原图片 API 地址解析为对应本地虚拟素材，封面选择与预览保持一致。
- **邮件不外发**：登录、策略、样文和结果通知进入演示收件箱，打开的是原确认与结果页。真正邮箱不会收到邮件；面试时应展示这里的结果页。
- **生产隔离**：Demo 构建关闭真实服务端 API，浏览器禁止外部请求，部署排除环境文件、状态与资料目录。误填的常见凭证字段和图片二进制也不写入演示状态或重放记录。

## 验收与复用

先完成构建，再启动本地服务。首次运行浏览器检查时，在临时目录安装测试工具，不修改业务依赖：

```powershell
npm.cmd install --prefix .tmp/demo-browser-tools --no-package-lock --no-save playwright
npm.cmd run typecheck
npm.cmd run validate:structure
npm.cmd run validate:monthly-naming
npm.cmd run test:demo
npm.cmd run test:demo:browser
npm.cmd run test:demo:interactions
npm.cmd run audit:demo
```

浏览器检查默认使用本机 Chrome。其他机器可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器可执行文件；用 `DEMO_BASE_URL` 指定另一个本地测试地址。

可用 `node scripts/demo-interactions.mjs --only "生成正文"` 定点复测公众号生成路径。定点报告单独保存，不覆盖完整交互报告；汇总时注明复测来源。

报告和截图生成在 `artifacts/demo-runtime/`，已排除 Git 与部署。交付时以本次实际报告为准：不要把“检查了某条路由”扩大成“穷举了全部按钮组合”。

后续 main 新增页面时，同步更新 `src/demo/routes.ts`、API 适配与测试，不新增复制的业务页面。升级 Next.js 时必须重新运行环境隔离测试与构建依赖审计，确认 `demo-env-guard.cjs` 仍有效。

## 隐私、部署与风险说明

- 不导入真实企业材料，不填写真实凭证、个人信息或客户数据。控制台有持续可见的演示标识。
- 数据量较大、长时间重复编辑可能达到浏览器存储上限；系统会给出提示，可重置演示场景。重置会丢弃本浏览器内的演示修改。
- 场景数据按当前自然月建立。跨月演示前重置一次；历史浏览器状态不会悄悄替换用户修改。
- 本地构建已禁用 dotenv 文件读取，并排除敏感目录。原始环境文件不做删除或改写。
- `vercel.demo.json` 提供独立 Demo 项目的构建配置；它不是默认生产配置。只有在明确部署 Demo 项目时使用，不能覆盖 main 的真实服务。Git 触发的 Vercel 构建若来自 `codex/demo-runtime`，构建入口自动选择 Demo 并固化运行标识；其他分支默认仍执行原生产构建。
- Demo 展示界面与流程能力，不证明模型真实执行质量、实际投递、渠道审核成功率或真实企业增长数据。
