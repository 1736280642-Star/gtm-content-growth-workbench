# GEO 官网审计与问题监控 P0-P4 实现说明

## 1. 结论

V5 现在把 GEO 监控拆成两条相互独立、在 MonthlyReview 汇合的证据线：

1. 官网监控：输入产品与官网 URL，后台真实抓取页面，输出确定性 Schema、技术可访问性、内容可抽取性与可引用性问题。
2. 问题监控：由人工从 GEO 策略推荐、已确认调研问题或手动问题中选择，按月在多个 AI 前台创建真实采集任务。

两条线不会互相改写。只有同一正式产品、同一月份且 AI 样本至少达到方向性门槛时，MonthlyReview 才允许形成“官网修复—问题复测”的相关性假设；系统不会自动声称因果关系，也不会自动修改下月 MonthlyPlan。

## 2. P0-P4 落地范围

### P0：双线工作台

- GEO 监控塔提供“官网监控”和“问题监控”独立入口。
- 用户只填官网 URL 即可创建审计；若 URL 域名与正式产品的 `official_url` 一致，系统会自动关联产品，也允许人工选择正式产品。
- 旧官网入口继续兼容，但会映射到新的官网监控页签。
- 总览只展示正式数据；MySQL 未配置时显示 `pending_config`，不生成模拟分数。

### P1：真实官网审计 Runner

- 使用 Sitemap 与站内 URL 范围抓取，默认最多 25 页，可通过 `SITE_AUDIT_MAX_PAGES` 调整，硬上限 100 页。
- 每个 URL 都执行公网 DNS 校验、重定向复验、12 秒超时、2 MB 响应上限与内容类型校验。
- 核心规则覆盖 title、description、canonical、robots/noindex、语言、H1、正文量、外部证据链接、可抽取结构和 JSON-LD。
- JSON-LD 检查包含 JSON 合法性、Schema.org 上下文、实体稳定身份字段和文章来源/时效字段。
- 对疑似客户端渲染页面按需调用 `SITE_AUDIT_RENDERER_URL`。未配置渲染服务时标为“尚未验证”，并撤销无法从静态 HTML 可靠判断的内容类问题，避免假阳性。
- `llms.txt` 与实验性 AI 发现文件单独展示，不进入核心准备度分。
- 每次运行保存页面快照、内容哈希、确定性证据、问题、整改任务及与上一次运行的新增/持续/已解决差异。

### P2：独立监控问题集

- 问题只能关联正式启用的 `product_entity`。
- GEO 调研中的产品名称先映射到正式产品 ID；无法确认映射的问题不会自动进入推荐列表。
- 策略推荐问题加入前仍需人工确认平台、优先级、每平台月样本量与自有官网域名。
- 同一产品的相同有效问题禁止重复创建；所有创建与状态变更具有幂等、乐观并发和审计记录。
- 月度调度器按“监控问题 × 平台 × 样本序号”创建幂等采集任务，并把样本时间均匀分布在当月；采集设备只能领取已到执行时间的任务。它不复用内容发布后的复测任务。

### P3：真实 GEO 指标

指标只读取最新正式 `capture_evidence`，证据源固定为 `ui_capture_real`：

| 指标 | 计算口径 |
| --- | --- |
| 品牌提及率 | 提及目标实体的成功回答数 / 成功回答数 |
| 官网引用率 | 至少引用一次自有域名的成功回答数 / 成功回答数 |
| 引用份额 | 自有域名引用出现次数 / 全部引用出现次数 |
| 引用中位排名 | 自有域名在引用列表中的 position 中位数 |
| 回答失败率 | 登录、适配、超时、中断、采集失败或取消任务数 / 全部任务数 |

提及率与官网引用率同时给出 95% Wilson 区间。成功样本少于 3 个为“样本不足”，3 到 19 个只支持方向性判断；只有总成功样本达到 20 个且每个已配置平台至少有 3 个成功样本，才标为可用于稳定判断。界面同时保留平台级拆分，避免用总平均掩盖单平台差异。

### P4：MonthlyReview 汇合与下月提案

- MonthlyReview 汇总官网运行分数、开放问题、严重问题及运行差异。
- 问题级复盘附带 GEO 指标、正式证据引用和同产品官网审计引用。
- 没有正式发布证据时，只有同时具备方向性以上真实 AI 样本和同产品高优先级官网问题，才允许人工创建关联型下月 Proposal。
- Proposal 只冻结证据引用，不自动创建月度任务、不自动改变配额，仍需下月 MonthlyPlan 人工审批。

## 3. 运行配置

数据库迁移：`database/migrations/20260816_032_v5_parallel_geo_monitoring.sql`。

后台进程：

- `npm run worker:v5-site-audit`
- `npm run worker:v5-geo-monitoring`

生产 supervisor 已包含这两个进程。可选配置：

- `SITE_AUDIT_MAX_PAGES`：单次最多审计页数。
- `SITE_AUDIT_RENDERER_URL`：受信任的浏览器渲染服务 POST 地址。
- `SITE_AUDIT_RENDERER_TOKEN`：渲染服务 Bearer 凭证；不得写入仓库或日志。

渲染服务请求体为 `{ url, waitUntil: "networkidle", maxBytes }`，响应体为 `{ html, finalUrl?, httpStatus? }`。渲染后的 `finalUrl` 仍会重新执行公网地址校验。

## 4. 可信度边界

- 官网准备度分是规则化诊断分，不是任何 AI 平台的官方排名分。
- 前台采集反映指定时间、地区、账号状态和平台模型下的观察结果，不代表全体用户看到相同答案。
- 官网问题和 AI 表现同时改善只构成实验线索。要判断修复效果，应保留修复前基线，在下一月用相同问题、平台和采集条件复测。
- 未配置正式 MySQL、浏览器渲染器或采集设备时，系统明确失败关闭，不使用本地假数据替代。
