# 多用户渠道账号连接与浏览器执行池

## 结论

托管用户不再分别理解三套授权逻辑。统一链路是：邮箱一次性登录 → 进入工作区 → 创建托管任务 → 依次连接知乎、CSDN、掘金 → 系统识别公开创作账号 → 用户确认 → 发布任务进入浏览器执行池 → 公开 URL 回传。平台密码、Cookie、Token 和浏览器存储不进入工作台业务数据库。

## 用户流程

1. 用户填写工作邮箱，邮件链接使用 URL fragment 携带一次性令牌，页面再通过 POST 兑换 HttpOnly 会话，避免令牌进入代理访问日志或被邮件扫描器提前消费。
2. 首次用户自动得到个人工作区；订单、产品链接、账号连接、授权会话和 Desktop 节点均按 `workspaceId` 隔离。
3. 用户在一个向导中看到三个渠道的完成进度。每个渠道只要求一次“登录平台”和一次“确认这个公开账号”。
4. 云端模式由执行池分配节点；私有化模式先生成一次性配对码，把当前设备注册为工作区专属 Desktop Connector。
5. Runner 从平台公开创作页识别昵称、头像和主页，工作台按渠道与平台账号标识生成指纹。识别不到真实名称时失败关闭，不能用浏览器 Profile 名称冒充账号。
6. 用户确认后，产品绑定只引用 `accountConnectionId`。正式发布前 Runner 再识别一次账号；指纹变化立即阻断。

## 多用户权限与隔离

| 角色 | 查看状态 | 创建授权会话 | 确认/替换账号 | 配对 Desktop 节点 | 修改托管设置 |
| --- | --- | --- | --- | --- | --- |
| `workspace_admin` | 是 | 是 | 是 | 是 | 是 |
| `product_owner` | 是 | 是 | 是 | 是 | 是 |
| `operator` | 是 | 是 | 否 | 否 | 否 |
| `viewer` | 是 | 否 | 否 | 否 | 否 |

同一工作区成员可以接续同一授权会话，但只有管理员和产品负责人可以最终确认账号。接口先验证邮箱会话，再验证工作区订单或产品归属；不存在与无权访问统一返回 404，避免泄漏其他租户资源是否存在。

## 执行池实现逻辑

- 执行节点使用一次性注册密钥或配对码换取随机节点令牌；数据库只保存 SHA-256 哈希。
- 授权、发布和验证统一写入 `browser_execution_job`。节点按能力、工作区、在线心跳和容量领取任务。
- 每次领取生成独立 Lease Token；节点最多并行处理自身容量允许的任务。20 分钟未完成的 Lease 可恢复，连续三次后失败并要求人工处理。
- 浏览器 Profile 使用不含业务语义的 `browserProfileRef`，目录位于仓库外。工作区、渠道和 Profile 三者不会共享浏览器存储。
- 发布任务携带 `accountConnectionId`、`browserProfileRef` 和 `accountFingerprint`。账号指纹核验发生在任何编辑器输入或发布按钮点击之前。

底层原因是多用户系统不能再用“某渠道当前登录了什么账号”作为全局状态；它必须把身份、业务归属、浏览器存储和每次执行同时绑定到同一工作区账号连接。对用户的直接影响是：不用复制凭据，也不用理解 Profile、端口或 Worker，但系统不会误发到同事或其他客户账号。

## 上线配置

部署侧配置 `HOSTED_PUBLIC_BASE_URL`、邮件投递接口、链接签名密钥、`PUBLISH_EXECUTOR_REGISTRATION_SECRET` 与 `JOTO_PUBLISH_RUNNER_TOKEN`。真实值只放在被 Git 忽略的 `.env` 或正式密钥服务中。云端交互浏览器若提供远程会话地址，必须使用 HTTPS；没有安全交互流时只能使用同机可见浏览器或 Desktop Connector，不能把未隔离的调试端口暴露给用户。

Desktop Connector 配对命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-desktop-publish-connector.ps1 -PairingCode <一次性配对码>
```

## 验收与故障边界

- 邮件令牌只能兑换一次，数据库与访问 URL 不出现原始令牌。
- 两个工作区不能读取或修改彼此订单、授权会话、产品和 Desktop 节点。
- 相同产品和渠道的账号绑定以工作区为唯一边界，不会互相覆盖。
- 节点离线、容量耗尽或 Runner 不可用时，任务保留或失败关闭，不伪造账号识别与发布成功。
- 验证码、手机确认和平台安全挑战始终由用户处理；系统不尝试绕过。
- 发布后只接受平台明确响应或可验证的公开 URL。未确认的点击状态不会盲目重发。

当前边界：仓库提供执行池控制面、节点 Worker、隔离 Profile 和安全交互 URL 接口；真正跨地域的云端浏览器画面仍需要部署受控的 HTTPS 远程交互服务。未配置该服务时，推荐 Desktop Connector，或让云端节点运行在操作者可见的受控桌面中。
