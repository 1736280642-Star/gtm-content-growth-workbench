## 一、结论

Phase 2D 的工程闭环已经完成：正式单篇正文不再直接拼接 Prompt Group 与 RAG 结果，而是在模型调用前确定性编译并冻结 `ProductionContractSnapshot content-production.v2`。首次生成与最多一次受限修复引用同一个合同哈希，正文、GenerationRun、DraftVersion 和审计事件可以沿合同回溯到产品策略、文章类型、规则包、渠道规则、表达校准和 FinalEvidencePack。

样稿人工门禁也已经落地：用户可以在现有正文预览抽屉中评分、提交结构化反馈、要求修改或确认通过。只有 Human actor 可以确认；确认通过会创建不可变 `ExpressionCalibrationVersion`，并把对应产品策略从 `pending_sample_review` 推进到 `production_ready`。模型、系统 Worker 和未来 Graph 都不能代替这个确认事件。

真实 WorkBuddy 内容质量尚未验收，但前置状态已经推进：`joto-workbuddy` 已完成三模型真实调研并形成 EvidencePack、待审 V5 策略包及 6 种候选文章类型。系统仍按正式门禁拒绝提前生成样稿，原因是用户尚未确认策略，而不是 Provider 配置缺失；没有用 mock 调研、旧通用 Prompt 或其他产品策略代替。

## 二、实现逻辑、底层原因与用户影响

| 改动                  | 实现逻辑                                                                           | 底层原因                      | 对用户的影响                                      |
| ------------------- | ------------------------------------------------------------------------------ | ------------------------- | ------------------------------------------- |
| 唯一生产合同              | 将任务、策略、文章类型、产品规则、渠道规则、表达规则/校准、证据包和推广决策冻结为 `content-production.v2`              | 模型不应在生成时临时选择事实和策略         | 用户验收的一篇样稿就是未来批量链路使用的真实合同，不是演示稿              |
| 合同持久化               | 模型调用前写入 `production_contract_snapshot`，GenerationRun、DraftVersion 保存合同 ID/Hash | 仅在内存拼 Prompt 无法复现和审计      | 可解释“这篇文章为什么这样写”，也能验证重试是否偷换规则                |
| 策略与文章类型 fail closed | 单篇任务必须绑定用户已确认策略及其中 active/frozen 的文章类型版本                                       | 通用 Prompt 回退会绕过用户策略确认     | 缺策略时明确阻断，避免产出看似完整但与产品策略无关的正文                |
| FactTrace 与正文解耦     | Provider 输出的 `originalQuote/sourceLocator` 被剥离；正文只保留自然事实表达，审计信息保留在合同和证据包       | 强制展示逐字摘录会破坏可读性并泄露内部审计结构   | 读者看到自然正文，内部仍能 100% 回溯事实                     |
| 一次受限修复              | 同一合同下只允许一次内容修复；取消证据拼接式 fallback                                                | 多次自动改写会逐步偏离已冻结策略和事实       | 失败会明确进入异常处理，不会悄悄生成质量不稳定版本                   |
| 样稿人工确认              | API 强制 `actorType=human`，评分低于 3 或仍有事实/结构/策略问题时禁止批准                             | 内容是否符合真实表达预期属于人的核心判断      | 用户只需验收最终正文，不需要理解内部 Blueprint、Prompt 或 Graph |
| 表达校准版本              | 样稿通过后冻结跨文章类型可复用的表达原则；文章结构仍由各文章类型版本决定                                           | 避免用一篇样稿覆盖所有类型结构，同时沉淀可复用偏好 | 后续批量正文可以引用同一校准版本，降低重复修改                     |

## 三、主要修改

### 3.1 生产合同

- `src/lib/v5/content-production-contracts.ts`
  - 合同升级为 `content-production.v2`。
  - 增加产品策略、文章类型、表达校准、生产模式和编译器版本引用。
- `src/lib/v5/production-contract-compiler.ts`
  - 表达校准指令进入确定性 Prompt 指令集合。
- `src/lib/v5/formal-production-contract-service.ts`
  - 从正式 MySQL 领域对象读取并编译合同。
  - 策略未确认、文章类型未绑定、证据不可用或规则冲突时 fail closed。
  - 合同在 Provider 调用前持久化并写审计事件。
- `src/lib/v5/single-article-production-service.ts`
  - 正式单篇入口改为“读取证据 → 编译合同 → 冻结合同 → 调用 Provider”。
- `src/lib/v5/formal-generation-service.ts`
  - Provider Prompt 只从合同生成。
  - 最多一次内容修复。
  - 不再把原始摘录要求为读者正文内容，也不再使用证据列表拼接式兜底文章。

### 3.2 样稿反馈与表达校准

- `src/lib/v5/sample-calibration-contracts.ts`
  - 定义五项 1-5 分质量评分、优点、问题类型、位置、修改要求和跨正文表达原则。
- `src/lib/v5/sample-calibration-repository.ts`
  - Human-only 决策、幂等冲突保护、不可变校准版本和审计。
  - 事实、结构或策略问题未解决时不能把样稿批准为生产基线。
- `src/app/api/v5/drafts/[id]/sample-review/route.ts`
  - 提供样稿状态读取与人工确认接口。
- `src/components/SampleArticleReviewPanel.tsx`
  - 接入现有 V5 正文预览抽屉，用户直接验收读者正文。
- `src/lib/v5/single-article-production-repository.ts`
  - Draft/Run 绑定合同；样稿生成成功后策略进入 `pending_sample_review`。
  - 样稿通过后由校准仓储推进到 `production_ready`。

## 六、风险与下一步

1. 不能把本阶段的自动测试文章当作 WorkBuddy 内容质量验收；它只证明合同与人工门禁可靠。
2. 当前结构/事实/策略类反馈会阻止批准并保留结构化问题，但自动派生新的文章类型版本、补资料任务或策略版本应由后续冷流程编排承接。
3. Phase 2E Graph 必须等真实样稿链路至少完整跑通一次后再接；否则会把仍在变化的样稿状态和反馈路由固化进图。
4. 样稿校准只保存跨类型表达原则，不能覆盖文章类型自己的结构定义。若后续不同文章类型差异明显，再按类型增加校准样本，不应在首期让用户一次验收多篇。
