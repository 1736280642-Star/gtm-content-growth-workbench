# 个人发件邮箱授权与 3027 验收指南

## 结论

工作台支持选择 QQ、163、Gmail 或 Outlook 作为部署级发件邮箱。登录链接、审核提醒、每日 URL 汇总和月度完成通知复用同一连接。

- QQ、163 使用 SMTP 授权码，不接收邮箱登录密码。
- Gmail 使用 OAuth 2.0 与 Gmail API，只申请 `gmail.send`。
- Outlook 使用 OAuth 2.0 与 Microsoft Graph，只申请 `Mail.Send` 和确认账号所需的 `User.Read`。
- SMTP 授权码与 OAuth Refresh Token 进入服务端后使用 AES-256-GCM 加密，数据库不保存明文。
- 真实值只由部署者本人写入被 Git 忽略的 `.env.local`，或在授权页的一次性表单中提交。不要把真实值放进命令、截图、Issue、聊天或仓库。

## 1. 部署前配置

在 `.env.local` 中由本人填写以下三项。不要复制真实值到公开文档：

```text
HOSTED_PUBLIC_BASE_URL=http://127.0.0.1:3027
HOSTED_EMAIL_SETUP_TOKEN=<部署级长随机值>
HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY=<32字节随机值，使用64位hex或base64>
HOSTED_EMAIL_OAUTH_REDIRECT_BASE_URL=http://127.0.0.1:3027
```

`HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY` 用于解密已保存的邮箱授权。擅自更换会使旧连接失效；需要轮换时，先替换密钥，再立即重新授权邮箱。

现有 HTTP Mail Relay 仍受支持。如果同时配置 `HOSTED_EMAIL_DELIVERY_URL` 和 `HOSTED_EMAIL_DELIVERY_TOKEN`，Relay 优先；要改用个人邮箱，应同时清空这两项。

## 2. QQ / 163 授权

1. 本人登录邮箱网页设置，开启 SMTP 服务。
2. 在邮箱后台生成客户端授权码；不要使用邮箱登录密码。
3. 打开 `http://127.0.0.1:3027/hosted/email-sender`。
4. 选择 QQ 或 163，填写发件邮箱、SMTP 授权码和部署级 Setup Token。
5. 点击“验证并连接发件邮箱”。系统先连接供应商验证，通过后才加密保存。

服务器固定使用：

| 邮箱 | SMTP 主机 | 端口 | 连接 |
|---|---|---:|---|
| QQ | `smtp.qq.com` | 465 | TLS |
| 163 | `smtp.163.com` | 465 | TLS |

## 3. Gmail OAuth

1. 在 Google Cloud 创建 OAuth Web Client，启用 Gmail API。
2. 注册精确回调地址：`http://127.0.0.1:3027/api/v5/hosted/email-sender/oauth/callback/gmail`。
3. 本人在 `.env.local` 填写 `HOSTED_EMAIL_GOOGLE_CLIENT_ID` 与 `HOSTED_EMAIL_GOOGLE_CLIENT_SECRET`。
4. 重建 3027，打开授权页，选择 Gmail，输入 Setup Token 后前往 Google 授权。
5. 只确认页面显示的发信与账号识别权限；若出现额外的读信权限，应取消并检查配置。

Gmail API 的正式发送方法是 `users.messages.send`，所需最小发送范围为 `https://www.googleapis.com/auth/gmail.send`。

## 4. Outlook OAuth

1. 在 Microsoft Entra 注册支持个人 Microsoft 账号的应用。
2. 增加委托权限 `Mail.Send` 与 `User.Read`，并允许 `offline_access`。
3. 注册精确回调地址：`http://127.0.0.1:3027/api/v5/hosted/email-sender/oauth/callback/outlook`。
4. 本人在 `.env.local` 填写 `HOSTED_EMAIL_MICROSOFT_CLIENT_ID` 与 `HOSTED_EMAIL_MICROSOFT_CLIENT_SECRET`。
5. 重建 3027，打开授权页，选择 Outlook，输入 Setup Token 后前往 Microsoft 授权。

正式发送调用 Microsoft Graph `POST /me/sendMail`，不使用已淘汰的 Basic Auth。

## 5. 重建与自动验收

代码、依赖、Dockerfile、Compose 或 migration 变化后执行：

```powershell
npm.cmd run docker:3027:deploy -- -NoOpen
```

部署器会在启动容器前检查 Worker 镜像内必须存在：

```text
/app/workers/browser-executor-worker.mjs
/app/scripts/check-hosted-identity-acceptance.mjs
```

随后执行：

```powershell
npm.cmd run typecheck
npm.cmd run validate:structure
npm.cmd run validate:monthly-naming
npm.cmd run test:v5-personal-email-sender
npm.cmd run test:v5-hosted-managed
npm.cmd run test:v5-multi-user-channel-connections
npm.cmd run test:formal-publish
npm.cmd run test:arcs-runner
```

不读取真实值的配置检查只允许输出 `SET` / `UNSET`：

```powershell
docker compose exec -T workbench-web node -e 'for (const key of ["HOSTED_EMAIL_SETUP_TOKEN","HOSTED_EMAIL_CREDENTIAL_ENCRYPTION_KEY","PUBLISH_EXECUTOR_REGISTRATION_SECRET","JOTO_PUBLISH_RUNNER_TOKEN"]) console.log(`${key}=${process.env[key]?.trim()?"SET":"UNSET"}`)'
```

## 6. 必须由本人完成的真实验收

自动测试不能代替邮箱供应商同意页与真实发信。本人完成授权后，按顺序验收：

1. 打开发件邮箱授权页，确认状态为“已连接”。
2. 在 `/hosted/login` 输入一个可收信地址，确认 15 分钟一次性登录邮件到达。
3. 点击邮件，确认建立 HttpOnly 会话并进入工作区。
4. 创建一项托管任务，确认回执邮件到达。
5. 完成一次知乎 / CSDN / 掘金账号连接与测试发布，确认公开 URL 自动回传并进入结果邮件。
6. 完成后撤销不再使用的旧授权码或旧 OAuth 授权。

任何一步失败时，系统应保持 `pending_config`、`retry` 或明确错误状态，不得把邮件或发布任务伪装成成功。
