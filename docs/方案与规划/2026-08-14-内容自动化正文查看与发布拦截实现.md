# 内容自动化正文查看与发布拦截实现

## 结论

内容自动化页面已支持在当前页面查看文章正文，并可人工拦截尚未发布的文章。拦截不是前端临时隐藏：任务会持久化为 `intercepted`，已创建且仍处于 `scheduled` 的机器发布排程会同步转为 `risk_blocked`，直接发布 worker 不再领取。

## 实现逻辑

1. 列表操作区新增“查看正文”，按需读取正式 DraftVersion，并在右侧 Drawer 中渲染 Markdown 正文。
2. “拦截发布”带二次确认，调用月度计划下的任务拦截 API。
3. 本地月度快照与正式 MySQL 矩阵项都支持 `intercepted` 状态；正式矩阵同时清空排程时间。
4. 发布账本按 `matrixItemId` 精确阻断仍处于 `scheduled` 的排程，不修改其他文章或已发布记录。
5. 顶部指标中，被拦截为红色、失败告警为橙色，其余业务数字为绿色；被拦截文章不计入待发布与流转中。

## 底层原因与用户影响

- 仅在页面隐藏文章无法阻止后台 worker，因此拦截必须同时落到月度任务状态和发布账本。
- 正文按需读取，避免列表接口携带所有正文导致页面体积和响应时间上升。
- 已拦截文章仍保留在队列中，便于追溯人工判断；当前版本不提供“恢复发布”，防止误操作重新进入自动链路。

## 后续建议

如业务确认需要恢复已拦截文章，应单独设计“重新批准并排程”动作，要求记录恢复原因并创建新排程，不应直接把旧 `risk_blocked` 排程改回 `scheduled`。
