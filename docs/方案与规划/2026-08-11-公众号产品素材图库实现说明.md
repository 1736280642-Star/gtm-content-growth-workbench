# 公众号产品素材图库实现说明

## 结论

工作台已经在“微信公众号生产”中内置产品素材图库，不接入第三方素材应用。当前闭环为：

`上传并沉淀素材 → 在正文配图建议处选择 → 写入预览与待发布 HTML → 发布时转存微信图片 CDN → 创建公众号草稿`

支持 JPG、PNG、WebP 和 GIF。素材必须归属一个已进入内容生产池的产品，并填写素材描述。

## 使用流程

1. 在“微信公众号内容生产”右上角进入“素材图库”，上传素材时标记对应产品并填写描述。
2. 生成微信公众号正文后，在正文预览上方的“正文配图工位”查看每条配图建议。
3. 点击“从素材图库选择”，从当前产品的素材中选择图片或 GIF；也可以替换或移除已选素材。
4. 选择结果会立即写入正文预览，并同步更新待发布 HTML、内容摘要和版本号。
5. 正式发布时，发布桥接服务把正文中的内部素材引用逐一上传到微信图文图片接口，取得微信 HTTPS 地址后再调用草稿创建接口。

## 实现逻辑

- 素材二进制保存在 `data/v5-media-library-assets/`，元数据、版本、幂等记录与审计记录保存在 `data/v5-media-library.json`。
- 正文数据只保存稳定引用 `workbench-media:<assetId>`，不保存磁盘路径，也不提前绑定临时外链。
- 预览 HTML 将引用解析为工作台受控内容接口，用户能直接看到实际图片或 GIF。
- 待发布 HTML 使用 `workbench-media://<assetId>`。发布桥接服务读取素材、校验状态与文件摘要、上传微信并替换为微信 CDN URL。
- 同一篇正文重复使用同一素材时只上传一次，再复用返回的微信 URL。
- 绑定、替换和移除都要求乐观版本号、幂等键、操作者与原因，并写入审计记录。

## 底层原因与用户影响

- 微信正文不能可靠使用工作台本地地址。发布前转存微信 CDN，才能保证草稿中的图片在公众号后台可访问。
- 选择时立即刷新预览，但延迟到发布时上传微信，避免用户反复替换素材产生无用的微信端文件。
- 素材被归档、跨产品、文件损坏或微信上传失败时，系统会在创建草稿前明确拦截，避免生成缺图草稿。
- 产品过滤由前后端同时执行，用户只看到当前产品素材，服务端也会拒绝跨产品绑定。
- 图库不按产品生成横向卡片或独立分区；产品增加后仍通过一个下拉框筛选，避免首屏随产品数量膨胀。

## 当前边界

- 当前为单文件上传，不支持批量上传。
- 不做 AI 自动识图、自动标签或描述生成。
- 素材不会预先同步到微信公众号永久素材库；仅在文章发布时转存正文图片。
- GIF 是否能原样进入最终公众号正文仍受微信接口、账号权限和微信侧格式限制；失败时会返回微信接口错误并停止创建草稿。
- 当前浏览器自动验收受本机 Chrome 无头模式 GPU 崩溃影响，功能以类型检查、结构门禁和服务测试覆盖。

## 后续触发条件

当同类操作重复三次以上，再考虑以下增强：

- 经常一次上传多份素材：增加批量上传与公共产品/描述前缀。
- 经常重复填写相似描述：增加 AI 描述建议，但保留人工确认。
- 同一素材频繁用于多篇文章：缓存微信侧上传结果，并增加失效检查。
- 需要复盘素材效果：记录素材与文章、发布日期、阅读指标的关联。
