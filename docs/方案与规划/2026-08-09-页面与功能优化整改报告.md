# 页面与功能优化整改报告

> 整改依据：《2026-08-06-页面与功能优化方案》
> 整改日期：2026-08-09

## 一、结论

本轮已把页面从“旧模块换标签”推进到真实的三类用户心智，并补齐支撑页面的主要后台能力。类型、结构、月度命名、MCP、MySQL 集成和 41 个页面/API 烟测均通过。

仍不能宣称真实外部业务全链路验收通过：需要选择一个真实推广产品，留下上传、调研、策略、正文、排程、公开 URL、24h/72h 存活和 GEO 复测的完整证据。

## 二、整改明细

### 2.1 后台闭环

- 新增产品策略编译：仅使用已批准 GEO 蓝图和正式资料快照，内容计划包含问题、内容类型、引用要求、复测基线和研究快照哈希；相同输入生成相同策略包 ID。
- 资料导入成功后自动重建来源快照、推进 GEO 调研并尝试编译推广产品策略，不再要求用户逐段点击。
- GEO 调研编排器增加推广产品自动协调：策略就绪后按蓝图复测基线创建幂等采集任务。
- 采集证据写入后，安全范围内的 `question_gap / citation_gap / competitor_change / ranking_drop` 自动写入策略执行调整和归因链；产品事实、定位与合规边界不自动批准。
- 自动排程读取每渠道账号、保守日上限、发布时间窗、最小间隔和已有占用；本月没有合适档位时保留为待迁移任务。
- 月末溢出由只读预览升级为下一月正式 MonthlyPlan 快照写入，使用确定性配额 ID 防止重复迁移，并重新执行策略预检。

### 2.2 内容自动化

- 删除五个功能型一级切换和“重新运行自动化”主按钮。
- 单页保留推广范围、自动化总览、产品运行状态、文章与排程队列四个区域。
- 推广产品通过抽屉集中选择；正常任务只显示状态和结果，只有真正需要用户处理的任务显示动作。
- 策略包改为只读抽屉，展示重点问题、渠道、数量原因、资料快照和规则包版本。

### 2.3 GEO 监控塔

- 四视角改为真实聚合页面，不再嵌入旧发布监控、Ledger、AI 单次任务和复盘整页。
- 总览显示推广产品、发布结果、指标回传、系统自愈和四要素用户告警。
- 发布明细下沉到文章详情抽屉；AI 可见性读取自动复测与问题级关联结果。
- 系统记录展示问题、策略、内容、排程和发布之间的关联。

### 2.4 设置与设备

- 每渠道增加发布账号、保守日上限、发布时间窗、最小间隔。
- 增加工作台内、邮件、Webhook 通知方式配置。
- 设备列表增加本机凭证说明、当前任务和最近成功采集时间。
- 新增一次性设备配对码：数据库只保存 SHA-256，原码只显示一次，10 分钟过期，成功使用后立即失效。

### 2.5 月度复盘

- 移除用户创建下月 Proposal 的主入口。
- 问题级复盘自动形成下一月决策基线，作为后续 MonthlyPlan 输入，不直接越权修改配额。

## 四、剩余风险

1. 月末溢出已实现正式写入，但缺少专门构造“已完成来源月 + 有未执行任务 + 目标月已有计划”的数据库集成夹具，暂不能仅凭结构检查认定所有边界通过。
2. 证据反馈当前形成策略执行调整与推荐追加数量；是否真正创建新增文章仍由下一次 MonthlyPlan 编译和正式门禁决定，避免绕过内容与事实审批。
3. 本地工作台配对码绑定固定本地工作区身份；未来接入多租户登录后应改为从认证会话读取 workspaceId/userId。
4. 真实外部发布与 24h/72h 验收仍依赖平台账号和时间窗口，必须另做受控真实产品验收。
