## 一、改造目标与范围

目标：把工作台从"多个功能页面"重构为三类用户心智——**产品与资料（告诉系统推广什么）、内容自动化（查看系统正在生产/发布什么）、GEO 监控塔（查看结果与自愈）**，并让全站"需你处理"口径一致。

范围：首页、产品与资料、内容自动化（路由 `/monthly-plan` 保留）、GEO 监控塔、设置、当日执行；公众号生产中心降级收纳。不改动核心业务逻辑，只调整呈现、入口与责任口径。

## 三、跨页面通用规范

### 3.1 责任状态标签规范

| 状态 | 标签 | 颜色 | 是否显示操作按钮 |
|---|---|---|---|
| 系统运行中 | 运行中 | 蓝 | 否 |
| 系统处理中 | 自动处理中 | 蓝/紫 | 否（仅查看详情） |
| 等待外部结果 | 等待平台 | 灰 | 否 |
| 需你处理 | 需你处理 | 红/金 | 是（唯一明确动作） |

### 3.2 告警卡片四要素

每条告警必须展示：发生了什么 / 影响什么 / 系统下一步做什么 / 预计何时再次检查。

示例：

> CSDN 登录状态检查失败。系统将在 14:20 进行第 2/3 次重试，4 篇文章已自动顺延，不会丢失。

### 3.3 需你处理清单规范

- 空态文案：`当前无需介入，系统会继续执行调研、生产、排程和回传。`
- 每条包含：任务名、产品、原因、系统已尝试次数、明确操作（补充资料/重新登录/确认事实）。

### 3.4 空态 / 加载 / 错误态

- 空态：给出下一步唯一动作（如"选择推广产品"）。
- 加载态：骨架屏，禁止出现空白页。
- 错误态：展示成因 + 下一步操作指引，不展示裸报错文本。

### 3.5 数据刷新

首页与监控塔保持 15 秒自动轮询；"需你处理"数据变化时页面顶部出现轻提示。

## 四、逐页改造方案

### 4.1 首页（[page.tsx](D:/GTM/工作台-main-v5/src/app/page.tsx)）

现状问题：把 `system_recovering`、资料不足计入"需人工处理"；完整展示七段流水线。

目标结构（四区块）：

1. **顶部结论**：系统正常运行 / N 项自动处理中 / N 项需你处理。
2. **产品进度行**：一行一产品：`腾讯云 ADP｜生成 18/24｜排程 12｜稳定发布 8`。
3. **系统动态**：最近自动完成的事件流（发布、回传、策略调整）。
4. **需你处理**：复用通用清单规范。

改造点：
- 修正责任聚合逻辑：`system_recovering`、`awaiting_material` 移出"需人工处理"（[page.tsx](D:/GTM/工作台-main-v5/src/app/page.tsx:161)、[page.tsx](D:/GTM/工作台-main-v5/src/app/page.tsx:206)）。
- 七段流水线区块替换为系统动态流。

数据源：`/api/v5/tasks/responsibility`、`/api/v5/tasks/attention`、产品进度聚合接口。

### 4.2 产品与资料（[products/page.tsx](D:/GTM/工作台-main-v5/src/app/products/page.tsx)）

现状：卡片式产品列表 + 资料上传，操作入口分散。

目标结构：

- 表格化一行一产品：产品名称 / 是否推广 / 资料完整度 / GEO 调研状态 / 策略状态 / 自动化状态。
- 操作列仅两个：`开始推广 / 暂停推广`、`补充资料`。
- 每行提供 `查看策略包` 入口（跳转内容自动化对应产品详情）。

改造点：
- 新增 `isPromoting`、`promotionStatus`、`strategyPackId` 字段展示。
- 资料更新后自动触发快照重建与重新调研，页面提示"系统已开始自动调研"。

### 4.3 内容自动化（[monthly-plan/page.tsx](D:/GTM/工作台-main-v5/src/app/monthly-plan/page.tsx)）

现状：顶部 Segmented 三段式切换 + "人工修改月度策略" Drawer，仍保留月度配置心智。

目标结构（单页四区块）：

1. **推广范围**：`正在推广 3 个产品` + 唯一主按钮"选择推广产品"（带搜索与复选框的抽屉）。
2. **自动化总览**：今日待发布 / 正在生成 / 已排程 / 需要处理（四个数字）。
3. **产品运行列表**：一行一产品，点击展开详情或右侧抽屉。
4. **文章与排程队列**：文章标题 / 产品 / 渠道 / 预计发布时间 / 状态；正常任务无操作按钮，异常任务显示唯一动作；生成后直接提供"查看正文"。

改造点：
- 删除顶部三段式切换。
- "人工修改月度策略"改为"查看策略包"（默认只读 Drawer：重点问题、推荐类型、渠道、数量及原因、版本、更新时间）；"高级调整"为二级入口。
- 保留路由 `/monthly-plan`，用户可见名称改为"内容自动化"。

### 4.4 GEO 监控塔（[geo-monitor/page.tsx](D:/GTM/工作台-main-v5/src/app/geo-monitor/page.tsx)）

现状：五个并列标签——发布状态 / 数据回传 / 官网监控 / 数据复盘 / AI 前台测试（[geo-monitor/page.tsx](D:/GTM/工作台-main-v5/src/app/geo-monitor/page.tsx:14)）。

目标结构（四视角）：

1. **总览**：所有产品 GEO 健康度、趋势、自动优化进度。
2. **内容表现**：收录、引用、阅读、转化及内容缺口。
3. **AI 可见性**：各 AI 平台品牌出现率、核心问题覆盖率、引用来源比例、与上一周期对比、系统已采取的优化动作。
4. **系统记录**：调研、策略调整、生产、发布、复测历史（含归因链）。

改造点：
- "发布状态""数据回传"移出标签，收敛到文章详情抽屉。
- 首页新增"需你处理"区块（只展示系统确认无法自愈的事项）。
- 采集设备、扩展、任务 Lease 不放监控塔，迁至设置 → 采集设备。

### 4.5 当日执行（[daily-execution/page.tsx](D:/GTM/工作台-main-v5/src/app/daily-execution/page.tsx)）

现状：独立执行页面，把 `system_recovering` 映射为"失败"（[daily-execution/page.tsx](D:/GTM/工作台-main-v5/src/app/daily-execution/page.tsx:79)）。

改造点：
- 修正责任映射：`system_recovering` → 系统处理中，不再计为失败/需人工处理。
- 页面降级为内容自动化中的"今日"区域；独立入口移入更多工具，短期保留兼容。

### 4.6 设置（[settings/page.tsx](D:/GTM/工作台-main-v5/src/app/settings/page.tsx)）

目标页签：

- 连接：发布账号连接、保守日上限、可发布时段、通知方式。
- 权限：角色与可见范围（收拢现有配置）。
- 采集设备：设备是否在线 / 支持平台 / 登录状态 / 当前任务 / 最近成功采集时间 / 适配器版本 / 撤销设备（管理员可见）。
- 规则检查：保留现有校验能力。

### 4.7 公众号生产中心（[free-production](D:/GTM/工作台-main-v5/src/app/free-production)）

- 移入"更多工具"折叠组，不做重构。
- 仅统一责任口径与状态标签，避免与主流程冲突。

## 七、验收标准

### 逐页验收

- [ ] 首页：`system_recovering` 不再计入"需处理"；空态显示"当前无需介入"。
- [ ] 产品与资料：一行一产品，操作仅两个，资料更新自动触发调研提示。

- [ ] GEO 监控塔：四视角可用；发布状态/数据回传不在一级标签；告警满足四要素。
- [ ] 设置：采集设备页签可用，设备可撤销。

- [ ] `npm.cmd run typecheck` 通过。
- [ ] `npm.cmd run validate:structure` 通过。
- [ ] 命名符合规范：路由/文档继续使用 `monthly-plan`、`monthlyPlanId`，不引入周维度概念。
