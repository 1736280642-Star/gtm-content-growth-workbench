# 自由内容生产类型化资料入口改造复盘

## 结论

自由内容生产已从“表达版本固定绑定产品和知识快照”调整为“类型模板定义写法，本次任务选择真实资料”。五类系统类型分别使用产品与知识库、事件事实、事件事实加会议文本三种入口，生成结果保存可追溯的来源片段快照。

## 实现逻辑

1. `FreeContentExpressionTypeVersion`只保留结构、表达规则、资料入口类型和发布规则。
2. `CreateFreeProductionInput`承载本次产品、知识快照、事件事实、会议文本和表达重点。
3. 服务端在创建任务前校验资料完整性，并把知识原文、人工事件和会议文本转换为来源片段快照。
4. 正文生成使用本次任务快照，不读取类型模板中的历史产品绑定。
5. 结果页以正文为主画布，右侧同时展示来源、封面和确认发布，不再通过步骤切换隐藏入口。
6. 每个正文事实声明必须在章节 `citations` 中绑定有效来源 ID；声明必须逐字出现在正文中。
7. 来源人工核对结果按正文产物 ID 持久化，正文变化后自动失效并要求重新核对。
8. 历史任务读取时保留原始审计数据，但发布判断和前台展示忽略废弃的 `launch_status`、`cta_url` 风险项。

## 底层原因

内容类型是稳定的写作规则，产品与资料是每篇正文的动态事实。如果二者共用同一版本对象，所有类型会继承同一个产品，用户也无法在生成前控制事实来源。将两者分开后，表达规则可以复用，事实仍由本次选择决定，并能形成独立审计快照。

## 用户影响

- 用户先选择资料再生成，不再生成后补救错误产品。
- 战略合作和活动内容可以录入多条可公开事件。
- 会议材料只粘贴纯文本或 Markdown，不需要上传和转写。
- 正文预览保持视觉中心，来源栏约占桌面页面四分之一。
- 来源、封面导入和确认发布始终可见；当前条件不足时仅禁用相应动作并说明原因。
- 历史任务仍可打开；没有来源快照的历史正文可以先补封面，但必须重新生成来源后才能发布。
- 任务列表直接显示“待核对来源、待补封面、待确认发布”等真实下一步，不再显示含义模糊的“待补充”。

## 维护规则

1. 新增内容类型时必须选择三种资料入口之一，不得写死产品 ID 或知识快照 ID。
2. 产品事实只能来自本次选择的生产就绪知识快照。
3. 人工事件必须包含时间、地点、人物、事件和公开确认。
4. 会议文本只接受粘贴内容，最大 10 万字，不接入文件上传或音频转写。
5. 来源面板保持极简展示，但后端必须保留快照 ID 和哈希用于审计。
6. 正文生成输出必须包含事实声明、来源 ID 和章节关系；发布前再次执行确定性引用检查。
7. 任何新正文都会清除上一版来源核对结果，禁止沿用旧确认。
8. 封面等不影响正文的发布素材独立保存，不触发无意义的正文重生成。

## 验证与发布边界

- `npm.cmd run typecheck`
- `npm.cmd run validate:structure`
- `npm.cmd run test:v5-free-production`
- `npm.cmd run test:formal-publish`
- 桌面端正文主列与右栏为约 `3:1`，正文最大宽度 `920px`。
- 移动端自动变为单列，来源与发布入口均可见且无横向溢出。
- 历史无来源快照夹具验证：封面入口可见，确认发布禁用，任务下一步为“待重新生成来源”。
- 自动化验收不得执行真实公众号发布；正式发布需要使用已授权账号和明确待发布正文单独验收。
