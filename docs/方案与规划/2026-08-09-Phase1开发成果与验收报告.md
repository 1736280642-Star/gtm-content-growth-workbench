## 四、改造详情

### 4.1 MCP Server 标准化

6 个 MCP Server 遵循统一的注册与错误处理模式：

- **基类约束**：loopback-only 基 URL、JSON 请求/响应、`toolResult`/`toolError` 统一 wrapper
- **工具注册**：`register(name, description, inputSchema, handler)` 统一注册函数
- **Schema 校验**：使用 `zod/v4` 定义输入参数，运行时类型安全
- **指令安全**：每个 Server 声明安全指令，如"禁止暴露原始凭证""禁止修改已发布内容"

各 Server 工具清单详见 [Phase 1 MCP 契约文档](2026-08-09-Phase1-MCP契约文档.md)。

### 4.2 Capture Devices 设备管理体系

采集设备全生命周期管理已就绪：

```
设备注册(POST /capture-devices) → 心跳保活(PUT /:deviceId/heartbeat) → 撤销(DELETE /:deviceId)
```

- **配对**：`deviceId + userId + platforms` 三元组注册，返回配对时间与在线状态
- **心跳**：定期上报 `lastHeartbeatAt`、`adapterVersion`、`status`，默认 5 分钟超时
- **撤销**：软删除，记录 `revokedAt`，设备不可再使用

### 4.3 Capture Task 任务矩阵

```
创建任务(POST /capture-tasks) → 领取租约(POST /:id/lease) → 上传证据(POST /capture-evidence)
```

- **幂等键**：每个任务携带 `idempotencyKey`，防止重复创建
- **租约机制**：默认 5 分钟 Lease，超时自动释放，设备可续租
- **证据不可变**：按 `artifactHash`（SHA-256）幂等，同一哈希不重复写入

### 4.4 归因链

`POST /api/v5/attribution` 记录性能下降 → 平台变化 → 证据 → 策略调整 → 文章 → 效果恢复的因果链：

- `sourceEventId`：触发事件 ID
- `platform` + `changeType`：平台与变化类型
- `evidenceIds` → `strategyAdjustmentId` → `articleIds` → `outcome`：完整因果路径

### 4.5 统一责任模型 API

- `GET /api/v5/tasks/responsibility`：按 `system`/`external`/`user` 三类聚合任务，前端不再把自动恢复状态计入"需处理"
- `GET /api/v5/tasks/attention`：仅返回 `userActionRequired = true` 的任务，展示四要素（发生了什么/影响什么/系统下一步/预计检查时间）

### 4.6 产品推广与策略包

- `PUT /api/v5/products/:id/promotion`：开启/暂停产品推广，返回 `isPromoting` 状态
- `GET /api/v5/products/:id/strategy-pack`：只读查看策略包（策略包 ID、状态、编译时间、内容计划）
- `POST /api/v5/products/:id/strategy-pack/apply`：应用策略包（含审批确认），`approved: false` 可拒绝
- `POST /api/v5/products/:id/source-snapshot`：触发资料快照重建

### 4.7 月末溢出任务

[monthly-overflow-service.ts](file:///d:/GTM/工作台-main-v5/src/lib/v5/monthly-overflow-service.ts) 实现：

- **状态检查**：判断当月是否标记为 `completed`/`review_ready`
- **任务筛选**：过滤 `published`/`cancelled`/`archived` 之外的任务
- **溢出判定**：当月未结束 → 任务仍在执行窗口；当月已结束 → 未执行任务标记为 `migrated`
- **API 入口**：`GET /api/v5/monthly-overflow?sourceMonth=2026-08` 查询状态，`POST` 执行溢出

## 八、结论

Phase 1 MCP 契约化改造任务已全部完成，TypeScript 类型检查与结构验证均通过（303/303）。核心交付：

1. **6 个标准化 MCP Server**：知识库、GEO 调研、RAG 检索、发布、复盘观测、采集任务，统一注册/错误处理/Schema 校验模式，契约文档齐备
2. **Capture Devices 全链路**：设备配对/心跳/撤销/任务矩阵/租约/证据上传，共 9 个 API 端点
3. **产品推广控制 API**：推广开关、策略包查看/应用、资料快照重建，共 4 个 API 端点
4. **统一责任模型 API**：责任聚合 + 需你处理清单，不再把自动恢复状态暴露给用户
5. **月末溢出任务**：自动识别未执行任务并迁移至下一月，不丢失、不要求重建
6. **归因链**：性能变化 → 平台变化 → 证据 → 策略调整 → 文章 → 效果恢复的完整因果记录
7. **数据库迁移**：5 新表 + 3 表扩展，为 Phase 2 AgentTeams 接入提供数据底座

Phase 1 为 Phase 2 AgentTeams 接入提供了完整的 MCP 契约基础、Capture 设备管理能力和统一责任判定体系。
