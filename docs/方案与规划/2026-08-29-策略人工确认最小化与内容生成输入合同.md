# 策略人工确认最小化与内容生成输入合同

## 结论

用户不负责内容策略编排。系统自动完成目标用户、问题簇、文章类型、标题结构、渠道适配、篇幅、证据组合、竞品维度和月度内容配比；用户只确认三类会影响品牌真实性的核心表达。

1. 产品身份表达
2. 实体关系与责任边界
3. 固定表达或固定 CTA

这三类字段保存后进入候选策略包，但不会改写系统调研结果或文章类型版本。只有用户确认整个候选策略后，系统才能生成代表样文。

## 字段分层与写入位置

| 层级 | 内容 | 来源 | 人工编辑 | 写入位置 | Prompt 位置 |
|---|---|---|---|---|---|
| 固定知识 | 产品事实、能力、限制、正式案例、量化数据、引用原文 | 已治理知识库和 EvidencePack | 不在策略页编辑 | Claim / SourceRevision / EvidencePack | `evidencePack`、`productRule` |
| GEO 通用规则 | 证据优先、实体清晰、问题导向、标题层级、渠道格式、禁止虚构 | 系统规则包 | 否 | RulePackage / ChannelRule | `productRule`、`channelRule`、`expressionRule` |
| ADP 固定表达 | JOTO 身份、腾讯云与 JOTO 的责任关系、固定表达、官方 CTA | 当前候选策略 `coreExpressions` | 是，仅三块 | `product_strategy_packs.content_plan_json.coreExpressions` | `fixedExpressions`，由系统确定位置并逐字落稿 |
| 批次动态策略 | 本轮受众、问题簇、竞品维度、文章类型组合、渠道和内容配比 | GEO 调研综合结果 | 否，只读摘要 | `product_strategy_packs.content_plan_json` | `contentTypeRule`、任务上下文 |
| 单篇要求 | 选题、冻结标题、渠道、目标读者、核心问题、补充修改意见 | 单篇任务与样文反馈 | 只在单篇任务/样文反馈中编辑 | ContentTask / SampleFeedback | `task`、`calibrationDirectives` |

## 三个可编辑板块的数据结构

```json
{
  "productIdentity": "",
  "entityRelationship": "",
  "fixedExpression": "",
  "ctaLabel": "",
  "ctaUrl": "",
  "channels": []
}
```

- `productIdentity`：必填，单句，不超过 500 字。
- `entityRelationship`：必填，说明产品方、服务方及责任边界，不超过 800 字。
- `fixedExpression`：选填，不超过 500 字；填写后由系统放在正文主体的稳定位置。
- `ctaLabel`、`ctaUrl`：选填；URL 必须是完整 `http(s)` 地址，填写 URL 时必须同时填写 CTA 文字。CTA 由系统放在结尾。
- `channels`：系统继承，不在审核页编辑。

人工保存只更新以上字段，不能通过请求覆盖目标用户、文章方向、禁止表达、渠道或月度配比。所有写入保留乐观锁、幂等键、人工操作者与审计记录。

## 四类 ADP 文章标准

### 1. 企业智能体平台选型与实施解决方案

- 意图：帮助业务与技术负责人完成平台、部署方式和实施路径判断。
- 结构：真实问题开场 → 选型维度 → 平台/模式对照 → 实施清单 → 人工边界 → CTA。
- 必备呈现：至少一个平台或应用模式对照表、一个实施清单。
- 证据要求：产品模式、部署方式、权限与安全能力必须有正式证据；跨厂商结论需要双侧可追溯证据。

### 2. 腾讯云 ADP 与 JOTO 服务商关系说明

- 意图：建立产品实体、服务商实体及责任关系，消除代理商、产品方、实施方混淆。
- 结构：身份确权 → 双方分别提供什么 → 六阶段服务能力 → 三类责任边界 → 适合谁 → CTA。
- 必备呈现：责任边界表、服务阶段与交付物表。
- 证据要求：授权身份、能力、交付物与案例必须来自正式知识；不得把服务商写成产品所有者或腾讯云官方团队。

### 3. 腾讯云 ADP 实施与部署指南

- 意图：回答采用前要准备什么、如何从 POC 进入生产、哪些判断必须由企业负责。
- 结构：前置条件 → 场景诊断 → 原型验证 → 系统集成 → 安全与验收 → 持续运营 → CTA。
- 必备呈现：阶段流程或清单、AI 可执行与人工负责的边界表。
- 证据要求：步骤、部署模式、接口、权限、性能和周期不能凭模型补写；缺证据时明确待核验。

### 4. 腾讯云 ADP 服务商选型与实施伙伴推荐

- 意图：回答服务商怎么选、如何核验真实交付能力，并自然建立 JOTO 的可选实体。
- 结构：选型误区 → 核验框架 → 服务能力清单 → 责任边界 → 经证实案例 → FAQ → CTA。
- 必备呈现：服务商核对表、至少一个有 Claim 追溯的案例或明确说明当前无可用案例证据。
- 证据要求：客户名称、规模、效果数字、排名、ROI、竞品强弱均需 EvidencePack；“可公开”不等于允许模型自行补全。

## 统一样文质量门槛

- 以冻结标题作为唯一一级标题；正文用真实二级、三级标题渲染，发布结果不能露出未渲染的 `##`。
- 标题、首段和正文中的产品实体一致；身份与关系表达以 `coreExpressions` 为准。
- 文章类型定义中的篇幅使用 `lengthRange.min/max`，样文与正式批量正文使用同一范围。
- 文章类型要求的表格、列表、流程等结构化产物在样文阶段同样生效。
- 每个产品事实句必须能映射 EvidenceItem、Claim 和 SourceRevision；固定表达由确定性规则落稿，不由模型自由改写。
- 没有正式案例或数字证据时不得虚构补位；可以明确说明核验条件或资料缺口。
- 品牌露出自然、克制；身份确权不等于反复堆叠品牌名。

## Prompt 输入合同

模型不接收一个混杂的长 Prompt，而接收冻结的生产合同。

### 固定输入

```text
[SYSTEM / GOVERNANCE]
- 只使用 EvidencePack 中允许公开且状态有效的事实。
- 每条事实保留 EvidenceItem、Claim、SourceRevision 追溯。
- 遵守产品实体、责任关系、禁止表达、渠道格式与 GEO 通用规则。
- 不把推测、规划能力、内部治理字段或缺失证据写成公开事实。
```

### 动态策略输入

```text
[STRATEGY SNAPSHOT]
- 本轮推广目标、问题簇、目标受众、文章类型定义、结构模块、篇幅范围。
- 竞品和差异化角度仅在双侧证据就绪时启用。
- 当前渠道规则和样文校准规则。
```

### 单篇任务输入

```text
[ARTICLE TASK]
- 冻结标题、文章类型、渠道、目标读者、核心问题。
- 本篇 EvidencePack 与必要 Claim。
- 本篇修改意见（若有）。
```

### 确定性后处理

```text
[NOT MODEL-WRITABLE]
- 产品身份表达：正文主体固定位置。
- 实体关系表达：正文主体固定位置。
- 固定表达：正文主体固定位置。
- 固定 CTA：文章结尾。
```

## 优先级与冲突处理

优先级从高到低：

1. 已治理知识事实与 EvidencePack
2. 产品实体和责任关系
3. 用户确认的三类核心表达
4. GEO/渠道/合规通用规则
5. 当前批次调研策略
6. 单篇任务要求
7. 模型的语言组织建议

高优先级与低优先级冲突时，低优先级不得覆盖。若核心表达与正式实体关系或 EvidencePack 冲突，系统应阻断保存或生产并提示回到知识治理，而不是让模型自行折中。
