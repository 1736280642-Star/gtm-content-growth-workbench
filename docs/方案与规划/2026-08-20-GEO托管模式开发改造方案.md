# GEO 托管模式开发改造方案

> 状态：代码改造与本地运行态验收完成；外部邮件投递和渠道账号待配置
> 日期：2026-08-20
> 适用范围：JOTO GTM Workbench V5 托管端
> 业务周期：严格归属于 `MonthlyPlan -> date execution -> publish and metrics -> MonthlyReview`

## 1. 改造目标

将当前“简化版运营控制台”改造成真正的 GEO 托管入口，使普通用户无需理解策略包、证据矩阵、发布生命周期和原始指标，只完成以下必要动作：

1. 提供产品资料和产品官网链接。
2. 选择推广渠道并完成必要的渠道授权。
3. GEO 调研完成后，通过邮件直达页确认策略。
4. 在同一审核中心确认代表样文。
5. 系统在 `MonthlyPlan` 内按渠道每日安全上限自动发布。
6. 当日批次关闭后，系统汇总公开 URL 并发送一封结果邮件。
7. 只有事实冲突、授权失效、平台阻断等无法自动处理的异常才要求用户介入。

目标体验不是“少看几个字段”，而是“任何时刻只出现一个明确的下一步”。

## 2. 用户活动主干

```text
提交资料
  -> 系统自动解析与 GEO 调研
  -> 邮件：策略待确认
  -> 同一审核中心：样文待确认
  -> 托管发布中
  -> 每日批次关闭
  -> 邮件：当日公开 URL 汇总
```

### 2.1 正常路径中的人工动作

| 阶段 | 用户动作 | 系统动作 |
| --- | --- | --- |
| 发起托管 | 官网 + 文件 + 渠道 + 通知邮箱 | 校验、持久化托管单、创建/绑定产品 |
| GEO 调研 | 无 | 资料治理、调研、策略包编译 |
| 策略审核 | 确认或提交一条修改意见 | 正式记录人工决策、排队生成样文 |
| 样文审核 | 确认或提交一条修改意见 | 冻结表达校准、推进 `production_ready` |
| 托管执行 | 无 | 在 MonthlyPlan 下生产、排程、发布、URL 回填、存活检查 |
| 日结果 | 阅读邮件；必要时处理异常 | 关闭当日批次、去重发送邮件 |

### 2.2 用户可见状态

托管端只允许暴露以下状态：

- `preparing`：准备中
- `pending_strategy_review`：待确认策略
- `pending_sample_review`：待确认样文
- `running`：托管发布中
- `action_required`：需要你处理
- `paused`：已暂停
- `completed`：本月已完成

内部正式状态继续保留，由托管编排层映射；不得修改或替代 V5 正式领域状态。

## 3. 核心设计原则

### 3.1 一次只要求一个判断

- 首页不再让用户在调研前选择文章表达、文章类型或策略参数。
- 策略页默认只展示目标用户、核心表达、渠道、内容方向和禁止表述。
- 样文页默认只展示标题、正文和计划渠道。
- 证据、指标、版本和审计细节只在“查看完整依据”中折叠展示，或留在运营控制台。

### 3.2 正常结果聚合，异常即时通知

- 单篇发布成功不单独发邮件。
- 当日批次关闭后只发一封 URL 汇总邮件。
- 授权失效、关键事实冲突和平台要求账号主体操作时即时发操作邮件。
- 可自行重试的问题不打扰用户。

### 3.3 复用正式能力，不建立第二真源

- 产品真源：`product_entity` 及现有知识治理表。
- GEO 策略真源：`product_strategy_packs`。
- 样文真源：`product_sample_article_task`、`draft_version`、`sample_article_feedback`、`expression_calibration_version`。
- 月度计划真源：现有 `MonthlyPlan` 正式合同与仓储。
- 发布结果真源：现有发布任务、公开 URL 和存活校验记录。
- 托管层仅保存委托偏好、对外状态、审核邀请、每日批次和通知投递，不复制策略或发布数据。

### 3.4 失败关闭与人工门禁

- 系统、Agent、调度器不得替代用户批准策略或样文。
- 未达到 `production_ready` 不得进入批量正式生产。
- 渠道未授权或不支持自动发布时不得伪装为“已连接”。
- 未获得有效公开 URL 时不得在结果邮件中声明发布成功。

## 4. 改造范围

### 4.1 托管提交

- 合并官网和文件为“产品资料”步骤。
- 支持选择已有产品或创建新产品。
- 移除“选择文章表达”。
- 渠道卡展示真实能力：`可自动发布`、`需要授权`、`仅生成草稿`、`暂不支持`。
- 每日上限默认使用系统安全上限；自定义上限放入高级设置。
- 托管单服务端持久化，替代 `sessionStorage`。
- 返回真实 `orderId` 和服务端状态。

### 4.2 托管审核中心

- 新增 `/hosted/review/[token]`。
- Token 只保存 SHA-256 哈希，具有作用域、有效期、单次使用和审计记录。
- 策略确认复用正式策略决策服务。
- 策略确认后立即排队生成样文。
- 样文生成完成后在同页展示；用户离开页面时由通知队列发送第二封邮件。
- 样文确认复用正式样文反馈与校准服务。

### 4.3 每日发布批次

- `DailyPublishBatch` 是 MonthlyPlan 下的执行聚合，不是独立计划周期。
- 有效日上限：`min(用户上限, 平台安全上限, 账号额度, 合格内容数)`。
- 批次关闭条件：达到有效上限或到达截止时间，且所有条目进入明确状态。
- 已发布条目必须已经获得 http(s) 公开 URL 并完成初次可访问校验。
- 同一产品、业务日期、批次版本的结果邮件只允许投递一次。

### 4.4 通知 Outbox

- 事件类型：托管已接收、策略待确认、样文待确认、当日批次关闭、需要用户处理、月度完成。
- 业务事务只写 Outbox，不同步等待外部邮件服务。
- Worker 负责投递、指数退避重试和失败记录。
- 未配置邮件供应商时保持 `pending/blocked`，不得伪造已发送。
- 邮件正文不包含内部证据 ID、密钥、账号授权信息或原始错误堆栈。

### 4.5 托管状态首页

- 回执页改为读取正式托管单，而不是浏览器会话。
- 只显示当前状态、唯一下一步、渠道、最近公开 URL、暂停入口。
- 普通用户不默认进入运营控制台。
- 运营控制台继续保留完整策略、排程、发布生命周期和指标。

## 6. API 与任务边界

### 6.1 面向托管用户

- `POST /api/v5/hosted/orders`：创建委托。
- `GET /api/v5/hosted/orders/:orderId`：读取用户状态和最近结果。
- `POST /api/v5/hosted/orders/:orderId/pause`：暂停或恢复。
- `GET /api/v5/hosted/reviews/:token`：读取当前唯一待办。
- `POST /api/v5/hosted/reviews/:token`：提交人工决策。

### 6.2 面向后台 Worker

- 扫描正式策略/样文状态并创建审核请求。
- 扫描当日发布执行结果并关闭批次。
- 扫描通知 Outbox 并投递邮件。

Worker 接口需要内部认证或仅通过进程内调用，不作为公开无鉴权入口。

## 7. 前端设计方向

### 7.1 页面单一任务

- 发起页：完成一次托管委托。
- 回执页：确认系统已经接手，并说明下一次何时联系用户。
- 审核页：只完成当前审核动作。
- 状态页：查看当前阶段和最近结果。

### 7.2 视觉语言

沿用已有 Handoff Desk 的沉静绿蓝体系，避免另起一套品牌：

- Ink `#18201d`
- Managed green `#176b52`
- Action blue `#2967a3`
- Surface `#f5f7f4`
- Border `#dce4df`
- Warning `#a34836`

标志性组件为“当前委托单”：像交接回执一样始终显示“系统已接手什么、现在做到哪里、用户是否要操作”。所有其他装饰让位于这一组件。

### 7.3 响应式与可访问性

- 移动端单列，主要操作按钮在可见区域内。
- 全部交互具备键盘焦点样式和明确 `aria` 文本。
- 状态不能只靠颜色表达。
- 尊重 `prefers-reduced-motion`。

## 9. 明确边界

本轮不做：

- 不重写 GEO 调研、策略编译、样文生成和正式发布引擎。
- 不创建另一套策略包、样文或发布结果表。
- 不允许系统自动通过人工门禁。
- 不建立独立的短周期计划或复盘；每日仅是 MonthlyPlan 的执行视图。
- 不把运营控制台字段复制到托管端。
- 不读取、打印或提交真实邮箱密钥、渠道 Token、Cookie 和私有链接。
- 不伪造第三方渠道已连接、邮件已发送或文章已公开。

## 10. 完成定义与验证

### 10.1 用户体验

- 新用户在 5 分钟内完成委托。
- 首次提交最多做三类决定：资料、渠道、通知邮箱。
- 没有异常时，进入托管发布后用户每日零操作。
- 邮件行动链接直达唯一待办，不要求在控制台中导航。
- 日结果邮件每批次至多一封，包含全部已获得的公开 URL。

### 10.2 领域和安全

- 策略和样文人工门禁保持有效。
- 每日执行归属于同月 `MonthlyPlan`。
- 所有写入具有幂等键、Actor、审计原因和版本控制。
- 审核 Token 不明文落库，邮箱和错误信息不泄露敏感数据。

### 10.3 工程验证

- `npm.cmd run typecheck`
- `npm.cmd run validate:structure`
- `npm.cmd run validate:monthly-naming`
- 新增托管合同、仓储、API、Token、Outbox、批次关闭专项测试。
- 搜索维护代码与文档，确认未引入过时的非月度周期标识。
- 浏览器验证桌面与移动端的提交、回执、审核、结果路径。

### 11.5 第三方渠道授权流程完善

知乎、CSDN、掘金采用“系统开通 + 用户授权”两层门禁：

```text
运营人员人工激活渠道规则
  -> 托管用户点击连接账号
  -> 系统打开项目目录外的专用浏览器 Profile
  -> 用户本人登录并处理验证码/手机确认
  -> 系统只检查登录态，不读取或回传 Cookie/Token
  -> 用户确认该专用账号用于当前产品
  -> 系统自动重新检查并继续 MonthlyPlan 执行
```
