# 月度内容矩阵四步页面重构复盘

## 结论

月度内容生产已拆分为四个独立路由：内容策略包、矩阵任务、内容生成、人工排程。四页共用可点击的 `MonthlyFlowNav`，前置条件不足时通过行动型空状态引导用户返回上一步，不再禁用导航。

## 实现逻辑与底层原因

- 用独立路由隔离策略、任务、生产和排程职责。路由负责保存用户所处阶段，刷新不再回到同页 Tab 默认项。
- 用 `MonthlyTaskTable` 统一矩阵任务页和内容生成页的标题、业务状态、阻塞原因、筛选和选择逻辑；页面只通过能力回调控制生成、修复、排程和删除操作。
- 将技术状态映射为“未生成、正在生成、已生成、已排程、已发布”，把待补资料、生成失败和 CTA 校验失败作为阻塞原因展示，避免状态维度混杂。
- 生成批次持久化 `queued/running/pausing/paused/completed/failed/cancelled`。暂停只把批次切到 `pausing`；当前 Provider 请求完成并保存后才进入 `paused`，从而避免半写入和重复成本。
- 策略项和任务删除写入审计记录。已批准策略通过新版本移除；已发布任务按归档处理；未发布任务保留删除快照，并计算策略配额缺口。

## 用户影响

- 用户可以直接进入任意阶段，并得到明确的下一步说明。
- “一键准入内容生成”不会调用 Provider；“一键生成”会在确认框中说明预计篇数，且不覆盖已有正文。
- 策略主表不再暴露内部版本 ID、来源、Prompt Hash 和原始 JSON；完整规则与 CTA 决策在详情弹窗中按自然语言查看。
- 当日执行筛选只影响当前日期表格，顶部全月统计保持不变；标题列使用剩余宽度并完整换行。
