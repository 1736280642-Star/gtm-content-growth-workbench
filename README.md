# 基于GEO的内容自动化工作台

以「知识与产品为输入、自动化内容增长为输出」的GEO自动化内容推广系统。发起托管只需三步：选择产品 / 上传资料、选择推广渠道、填写结果邮箱，其余由系统自动完成，关键节点通过邮件确认。

## 托管模式（默认入口）

```text
产品资料 + 产品官网 + 推广渠道 + 结果邮箱
              │
              ▼
GEO 调研 → 邮件确认策略 → 邮件确认代表样文
              │
              ▼
按渠道每日安全上限自动发布 → 邮件回传公开 URL 汇总
```

人工默认只处理：首次提交资料、选择渠道、确认策略、确认样文，以及授权失效等少量异常。

知乎 / CSDN / 掘金使用「专用浏览器登录 + 本人确认账号」，不要求用户提交密码、Cookie 或 Token：

```text
一次性邮箱登录 → 个人工作区 → 统一三渠道连接向导
              │
              ▼
平台登录 → 识别公开创作账号 → 用户确认 → 生成工作区级账号连接
              │
              ▼
浏览器执行池（云端节点 / Desktop Connector）→ 发布 → 公开 URL 回传
```

## 完整运营链路

```text
产品 + 知识 → GEO 调研 → 问题/关键词池 → 月度策略 → 内容矩阵
                                                      │
                                                      ▼
自动排程 → 发布回传 → 数据复盘 ────────────► 下一自然月策略输入
```

## 能力边界

**当前能够完成**：产品绑定与知识导入、多供应商联网调研、策略包生成、内容矩阵、正文生产、自动排程与发布、URL 回传、AI 前台测试、月度复盘。

**当前不能承诺**：

- 不伪造「已生成 / 已发布」结果；成功以平台公开结果、公开 URL 与存活验证为准；
- 不绕过各平台登录、验证码、账号资质、风控与内容审核；
- 真实推广前必须人工确认策略与代表样文；
- 托管入口已具备邮箱登录、工作区隔离与角色门禁；运营控制台、计费、企业 SSO、集中密钥托管与合规运营仍是公网 SaaS 上线前置项，不能把本地 3027 直接暴露到公网。

## 主要模块

| 模块 | 路径 | 职责 |
| --- | --- | --- |
| 首页 | `/dashboard` | KPI、七阶段流程、内容产线与人工待办 |
| 知识库 | `/knowledge` | 产品绑定、知识导入、GEO 调研、问题/关键词池、持续采集 |
| GEO 内容中心 | `/monthly-plan` | 自然月策略、矩阵任务、正文生成与排程 |
| 公众号内容生产 | `/free-production` | 单篇内容生产：类型、补充、正文、复检、发布队列 |
| 内容监控塔 | `/content-monitor` | 发布状态、数据回传、官网审计、AI 可见性 |
| 设置 | `/settings` | 模型、连接、规则、权限、日志配置 |

AI 前台自动测试复用已绑定账号，后台自动发送问题、采集回答与引用并回传脱敏证据：

```text
点击已绑定 AI 账号 → 创建绑定任务 → 扩展后台新会话 → 采集/回传 → 自动关窗
```

首次配置与账号绑定见 [`browser-extension/README.md`](./browser-extension/README.md)。

## 技术结构

```text
Next.js Web/API
  ├─ MySQL：业务状态、任务、治理与发布记录
  ├─ OpenSearch：RAG 关键词与向量检索
  ├─ knowledge/geo workers：知识刷新、站点采集、GEO 调研
  ├─ monthly/content workers：策略、任务、正文与排程
  └─ publish/browser-executor workers：发布、重试、回传与执行池
```

## 快速开始

```powershell
.\setup-full-production.cmd   # 首次完整初始化，只需输入 DASHSCOPE_API_KEY
npm.cmd run docker:3027       # 日常启动
npm.cmd run dev:3027          # 本地开发
```

访问 <http://127.0.0.1:3027>；完整健康检查 `GET /api/health?deep=true`（仅 `profile=full` 且 MySQL / OpenSearch / Embedding / Workers 全部 `ready` 才通过）。
